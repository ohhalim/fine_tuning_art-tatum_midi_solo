# 이력 + 낮은 온도 + 패턴 캐시 런타임의 fallback 줄이기 (사전 등록)

작성 2026-10-02. 이슈 #1610. 판정 규칙은 실행 전에 고정했다. 독립 리뷰는 사용자 지시로 나중에 일괄로 받는다. `musical_quality_verified: false`.

## 근거 (#1608)
- 런타임 R(이력 256 + T 0.6 + 패턴 캐시)은 동기 재사용 0.072, 코드톤 +0.054였다
- 그러나 fallback이 12건 났다
  - 준비 시간 초과 7건: 생성 p50 369 ms, 최대 529 ms. 시작 예산 β 0.5는 약 469 ms다
  - 검증 실패 5건: 생성 예산 96토큰 안에 블록을 못 채운 것으로 추정한다

## 질문 (하나)
미리 정한 두 설정 중 하나라도 동기 재사용과 코드톤을 유지하면서 fallback을 0으로 만드는가.

## 설정 (고정, 나머지는 #1608 R과 같음)
| | 이력(carry) | 시작 예산 β | 생성 예산 | 비용 |
|---|---|---|---|---|
| G1 | **128**토큰 | 0.5(auto) | 96 | 앞 문맥이 짧아진다 |
| G2 | 256토큰 | **0.9** | **128** | 입력 반영이 약 0.4블록(128 BPM에서 375 ms) 늦어진다 |
- `--max-sequence 512`: G2의 primer 최대 길이는 256 + 48 + 128 = 432다

## 측정과 판정
- 진행 3개 × seed 42·43 = 설정당 6회. 기준 A는 기본 런타임(#1608과 같음). 판정은 `scripts/runtime_coherence_check.py`로 한다
- 설정별 **통과:** 모두 충족
  1. 동기 재사용 ≥ 0.0365
  2. 코드톤 짝 평균 차이 ≥ −0.03
  3. 6회 모두 fallback 0(미스는 보고만)
- 둘 다 통과하면 G1을 고른다(지연이 짧다). 하나만 통과하면 그것을 고른다. 둘 다 미달이면 기록하고 이 단위에서 더 탐색하지 않는다
- 고른 설정은 `play_personalized`/`fl_live`에 **opt-in 프리셋 옵션**으로만 넣는다. 기본값은 청취 후 결정한다

## 결과 (2026-10-02): 두 설정 모두 **불통과**. G2는 fallback 1건으로 아깝게 미달
원시값 `outputs/runtime_cache_fallback/{G1,G2}/`(`check.json` 포함, git 미추적). 사전 등록은 실행 전 커밋(276d383d)이다. 부하 평균 4.2–5.8.

| | 동기 재사용 | 경계/내부 | 코드톤 짝 차이 | fallback(원인) | 미스 | 생성 ms p50 / 최대 |
|---|---|---|---|---|---|---|
| A 기본 런타임 | 0.001 | 1.743 | — | 1 | — | — |
| #1608 R(이력 256, β 0.5, 96) | 0.072 | 1.898 | +0.054 | 12(시간 초과 7, 검증 5) | 0 | 369 / 529 |
| G1(이력 128, β 0.5, 96) | 0.0359 | 1.507 | +0.068 | 13(시간 초과 8, 검증 5) | 0 | 346 / 564 |
| **G2(이력 256, β 0.9, 128)** | **0.068** | 1.734 | +0.032 | **1(검증 1)** | 0 | 368 / 643 |

- G1
  - 동기 재사용이 기준 0.0365에 근소하게 못 미친다
  - fallback도 줄지 않았다. 이력을 줄여도 생성 시간이 거의 그대로였다(p50 346 ms)
  - → 불통과
- G2
  - 이른 시작(β 0.9)으로 시간 초과는 0건이 됐다
  - 생성 예산 128로 검증 실패도 5건에서 1건으로 줄었다
  - 동기 재사용(0.068)과 코드톤 조건은 충족했다
  - fallback 1건으로 조건 3(0건)은 **미충족** → 불통과
- 참고: 기준 A(기본 런타임)도 같은 6개 조건에서 fallback 1건이었다. G2의 실시간 안정성은 지금 기본 런타임과 같은 수준이다. 사전 기준은 0건이라 판정은 그대로 둔다
- G2의 비용: 입력 반영이 약 0.4블록 늦어진다

### 정리
- 사전 등록대로 이 단위에서는 프리셋 opt-in을 추가하지 않는다. 더 탐색하지도 않는다
- 다음은 사용자 청취다. 같은 진행·seed의 A와 G2를 들어 보고 "말처럼 이어지는지" 판단을 받는다. 기본값과 프리셋 반영은 그 결과로 정한다

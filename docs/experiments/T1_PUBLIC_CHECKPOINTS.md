## 질문 (하나)
**이 특정 공개 체크포인트가 지금 BebopNet(N1/N2)보다 사용자 목표에 맞는가.** 목표는 코드에 맞고, 릭이 들어가고, 연결이 자연스러운 비밥 솔로다.

- 학습 데이터, epoch, 표현이 모두 다르다. 그래서 "명시 코드 조건 구조가 더 낫다" 같은 아키텍처 인과 주장은 하지 않는다
- 품질 판정은 사용자 청취다. 자동 지표는 진단만 한다

  - HSE 포크와 `model.py`·`layers.py`가 같다(git blob 일치 확인)
  - 8마디 체크포인트를 고른 이유: N1/N2와 같은 길이다. 데이터를 보기 전에 정했다
- **MINGUS**: 생성할 때 WJazzD 원본(XML 약 90 MB + CSV 약 20 MB)으로 어휘를 다시 만들어야 한다. 이 데이터 다운로드는 아직 승인되지 않아 이번에는 하지 않는다. 승인되면 같은 계약으로 별도 실행한다
- **기준**: N1(BebopNet 기본), N2(BebopNet 화성 탐색). 이미 사용자에게 올린 파일 그대로다

## 실행 계약 (T1-a)
- **진행:** Gm7–C7–Fmaj7–Fmaj7 × 2(8마디), 128 BPM, 같은 guide 컴핑(C3–B3), 같은 피아노 렌더
- **CMT 입력:**
  - 16분음표 격자, 마디당 16프레임. 프레임마다 그 순간 코드의 12차원 크로마를 넣는다. 마지막 프레임 다음 칸(129번째)은 진행을 이어서 Gm7로 둔다
  - 시작 마디: HSE 기본값인 `tonic_held`(첫 프레임 G4 onset, 나머지 15프레임 sustain)
  - 샘플링: 체크포인트 hparams의 `topk: 5`(pitch). rhythm은 원 코드대로 top-3
  - 출력 시간은 CMT 고정 격자(120 BPM 상당)이므로 128 BPM으로 비례 변환한다
- **처리:** 원 출력(raw)과 처리본을 따로 저장한다. 처리본은 아래 세 가지만 바꾼다
  - 128 BPM 시간 변환
  - velocity 90 고정(N1/N2와 같다. BebopNet도 출력 velocity가 전부 90이었다)
  - 2:1 스윙(`lick_bank.swing`). CMT 출력은 스트레이트 16분음표고, BebopNet은 자체 스윙 출력이다. 스윙은 렌더 처리이지 모델 출력이 아니라고 표시한다
  - 음 재선택, 충돌 정리, 마스크, 옥타브 이동은 하지 않는다. 음역이 피아노 오른손에서 벗어나도 그대로 둔다
- **seed:** 1–4를 생성한다. 청취에 올리는 것은 seed 1·2로 미리 고정한다. 좋은 샘플을 고르지 않는다. 실패, 무음, 오류도 그대로 보고한다

## 코드 반응 진단 (T1-c, 보고만)
- 같은 seed로 진행 두 개를 넣는다
  - P = Gm7–C7–Fmaj7–Fmaj7
  - Q = Gm7b5–C7–Fm7–Fm7. 근음은 그대로 두고 품질만 바꾼 진행이다
- P와 Q가 다른 음(Gm7의 D ↔ Gm7b5의 Db, Fmaj7의 A·E ↔ Fm7의 Ab·Eb)만 센다. 출력 Y_P와 Y_Q 각각이 자기 조건 쪽 음을 더 많이 쓰는지 2×2 표로 본다
- 출력이 달라졌는지만 보는 비율은 성공 기준으로 쓰지 않는다

## 청취 (T1-d)
- 익명 쌍대 선호: N1, N2, CMT seed 1, CMT seed 2를 무작위 글자로 섞어 올린다. 매핑은 페이지에서 접어 둔다
- 사용자에게 받을 것: 전체 선호, 그리고 화성·릭·연결감 메모를 따로
- 실제 비밥 피아니스트의 오른손을 같은 피아노로 렌더한 기준 클립 하나를 함께 둔다(이미 있는 RH_Barry). 음색이나 렌더에 대한 불만을 모델 문제와 분리하기 위해서다
- 올리기 전에 모든 클립을 마디별 음 단위로 덤프해 읽는다(음 이름, 코드 도수, 컴핑과 실제 울리는 음정, 길이)

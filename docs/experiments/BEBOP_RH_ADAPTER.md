# 비밥 오른손 어댑터 (사전 등록)

작성 2026-10-02. 이슈 #1618. 판정 규칙은 학습 전에 고정했다. 독립 리뷰는 사용자 지시로 나중에 일괄로 받는다. `musical_quality_verified: false`.

## 근거
- 사용자 선택: D1 방향(실제 비밥 피아니스트의 오른손 + 짧은 컴핑)
  - D2(교본 같은 릭)도 좋지만 연습 교본처럼 들린다고 했다. D2의 장점인 코드음 착지와 쉼은 평가에서 함께 본다
- 데이터: `data/bebop_rh`(#1616). train 189곡, val 28곡, test 18곡. 초당 3.7음, 프레이즈 16음

## 학습 (완성 Tatum 레시피와 같음)
- 공통 base, LoRA out_proj + QKV r16, lr 3e-4, batch 4, accumulation 4, cosine, LS 0.1, seed 42, MPS
- `--planned-epochs 43`(train 189곡이면 epoch당 약 12 update, 약 518 update)
- 스냅샷을 val로 고르지 않는다. 마지막 스냅샷을 쓴다. val CE는 보고만 한다
- 출력은 `outputs/bebop_rh/run`, `outputs/bebop_rh/export`다. 기존 체크포인트는 건드리지 않는다

## 평가 (test 18곡, 오른손 토큰)
- 위치: 곡마다 최대 8곳(`pick_positions`). primer는 앞 256토큰의 실제 오른손 선율이다
- 자유 생성: 4초, T 1.0, top-k 32, top-p 0.95, grammar mask, seed 2개
- 비교: 공통 base(어댑터 없음)와 비밥 어댑터. 같은 위치·seed를 쓴다
- 지표: 생성과 실제 이어지는 4초에 똑같이 적용한다(합산 기준)
  - 초당 음 수
  - 쉼(≥ 0.3초) 시간 비율
  - 10초당 쉼 횟수
  - 쉼 사이 프레이즈 길이 중앙값
  - 유효율

## 판정 (학습 전 고정, 기준은 실제 test 이어지는 구간 값)
- **통과:** 비밥 어댑터가 모두 충족
  1. 초당 음 수가 실제의 0.67–1.5배다
  2. 쉼 시간 비율이 실제의 0.5배 이상이다
  3. 프레이즈 길이 중앙값이 실제의 2배 이하다
  4. 유효율 ≥ 0.9
  5. 초당 음 수가 base보다 실제에 가깝다(|log(생성/실제)|가 더 작다)
- 통과하면 런타임 통합(오른손 생성 + 짧은 3음 컴핑)과 청취를 다음 단위로 한다. 미달이면 기록하고 이 단위에서 레시피를 다시 탐색하지 않는다

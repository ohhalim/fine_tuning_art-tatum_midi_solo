# Aria Mehldau base vs adapter, 같은 형식 마스크로 생성 (#1731) — 사전 등록

#1726 pilot은 마스크 없는 생성에서 유효성 미달이었다(adapter 1/8, base 5/8). 진단(#1728)에서 고정 오류 지점의 비피아노 질량은 adapter가 컸다(R1-E). 생성 전체로는 사전 기준에 못 미쳤고(R1-S 불분명), 탐색 분해로는 증가가 dur 자리에 몰려 있었다.

이번에는 base와 adapter에 **같은 형식 마스크**를 거는 새 운용 조건에서 생성한다. 실제로 쓸 수 있는 출력에 차이가 남는지 보는 작은 실험이다(아스트라 결정).
- 진단을 통과해서 받는 보상이 아니다. R1-E/S 조건은 미충족 그대로다. 새 운용 조건을 평가하는 별도 결정이다
- #1726 판정(개발 미달, test 미개봉)은 그대로다. 마스크 없는 #1726 생성은 별도 기준선으로 둔다

## 질문

1. 마스크가 각 모델의 선택에 얼마나 개입했나? 마스크 전 허용 질량, 마스크가 선택을 바꾼 step 수
2. 출력의 결함(길이, 반복, 동시음, train 16-gram)은 어떻게 다른가? **기술만 한다**
3. 같은 음색 렌더로 블라인드 청취 세트를 만든다. 청취는 선택이다

## 고정 조건

- frozen `model-gen.safetensors` + #1726 `lora_u128.pt`(SHA를 #1726 보고서와 대조)
- #1726 개발 prompt 4개(처음 8초) × seed 1, 2 × base / adapter = 16개. #1726과 같은 순서
- 새 토큰 512개, temperature 1, min_p 없음, `<E>`에서 멈춤
- 재선택, 재시도, 좋은 표본 고르기 없음

## 마스크 (`scripts/aria_grammar_mask.py`) — 형식만

`aria_token_validity`의 규칙을 샘플링 전에 적용한다.
- 음 사이: 피아노 음 시작, `<T>`(구간 리셋), `<D>`, `<E>`
- 음 시작 뒤: 그 5초 구간의 마지막 onset보다 앞서지 않는 onset(같은 값은 허용, 화음)
- onset 뒤: dur
- 코드톤, 음역, 반복 억제, 밀도 유도는 넣지 않는다
- 허용 집합이 비거나 마스크 전 허용 질량이 비유한·0이면 그 step에서 멈추고 기록한다

**샘플러:** #1726과 같다. `torch.multinomial(p, 1)`은 step마다 vocab 전체에 Exp(1) 노이즈를 하나 뽑아 `argmax(p / 노이즈)`를 고르는 것과 같다(#1728에서 확인). 마스크는 이 argmax를 허용 토큰 안에서만 고른다.
- 마스크 없는 선택이 이미 허용 토큰이면 결과는 같은 토큰이다
- 그래서 #1726에서 유효했던 6개(base 5, adapter 1)는 #1726과 같은 토큰열이 나올 것으로 예상한다. 무효였던 10개는 #1726의 첫 오류 위치까지 같고, 거기서부터 갈라진다
- 이것은 수치 경로 검증 정보로 보고한다. 중단 조건은 아니다. 깨지면 원인 불명으로 적고, 마스크 효과로만 돌리지 않는다(아스트라 실행 전 리뷰)

## 기록

- **매 step:** 마스크 전 허용 질량, 마스크가 선택을 바꿨는지(바꿨다면 문법 상태와 원래 선택 토큰)
- **스트림마다**
  - 형식 유효성: 마스크 구현 검사다. **각 스트림을 끝낼 때마다** 검사해서, 하나라도 무효면 구현 결함으로 보고 그 자리에서 멈춘다. 마지막에 16/16 완료도 다시 확인한다. **개인화 성공 지표가 아니다**
  - 마스크 개입: 바꾼 step 수(상태별), 첫 개입 위치, 허용 질량 최소, 0.999 미만인 step 수, 평균 비허용 질량
  - #1726과 같은 토큰이 이어진 길이
  - 결함 기술
    - 음 수, 음역, 최장 반복, 최대 동시음
    - 끝 연장(초): prompt 최대 note-end 대비
    - 새 음 구간(초): 새 음의 첫 onset부터 마지막 end까지
    - `<E>` 종료 여부, train 16-gram 일치 수
- 결함 지표는 결함을 기술할 때만 쓴다. 개인화나 음악성 점수로 승격하지 않는다

## 렌더와 블라인드 세트 (`--render`)

- 16개 전량 MIDI(prompt + 생성). cap에서 음 중간에 끊긴 마지막 음은 뺀다. 모두 피아노 program 0인지 검사한다
- 모두 같은 음색(GeneralUser GS v1.471, fluidsynth 44.1 kHz)으로 렌더한다
- 같은 prompt·seed의 base / adapter를 한 쌍으로 묶어 8쌍. A/B는 `random.Random(2026)`으로 섞는다
- 정답표 `key.json`은 저장소 밖에 두고, 저장소 보고서에는 그 SHA만 적는다
- 청취는 선택이다. 청취가 없으면 선호는 미확인으로 끝낸다. 청취를 실행 조건으로 요구하지 않는다

## 비용과 중단

- 예상: #1726 같은 단계 생성이 마스크 없이 2,357초(39분)였다. 문맥 전체를 매번 다시 계산한다(KV 캐시 없음). 마스크 비용은 작다
- **wall 상한 3,600초.** 스트림 시작·끝, 128토큰마다 진행 로그를 남긴다. 상한에 걸리면 그때까지의 결과를 기록한다. 예산을 늘려 다시 돌리지 않는다
- **중단 시 보존:** 생성 원자료는 `{"completed": [...], "incomplete": ...}`로 저장한다. 멈춘 순간 진행 중이던 스트림은 그때까지의 토큰·허용 질량·개입 기록에 `stop_step`·`stop_reason`을 붙여 `incomplete`에 따로 둔다. 형식 유효성 판정과 렌더 입력은 `completed`만 쓴다(아스트라 실행 전 리뷰 M1)
- 즉시 중단: 입력 SHA 불일치, MPS fallback, 샘플러 동등성(합성 32회) 불일치, 허용 집합 비어 있음·허용 질량 비유한·0, 형식 유효성 16/16 미달
- 새 유료 자원, 외부 다운로드, 공개 업로드 없음. 생성 원자료, MIDI, wav, 정답표는 저장소 밖 `/Users/ohhalim/git_box/mehldau_aria/masked/`에 둔다

## 고정 설계
### 사례
- 모델 3개: Tatum 완성(`outputs/final_tatum/export/checkpoint_update518.pt`), 멜다우 #1497(`outputs/clean_base/c2_export/checkpoint_update128.pt`), 공통 base(`outputs/tvm/common_base/checkpoint_epoch8.pt`)
- 문맥 세션: 그 모델의 기존 런타임 실행 리포트(`played_bars` = 채택/예약되어 연주된 블록). 기본 런타임, temperature 1.0
- 블록 k(반 마디 단위): 세션 블록 수가 n일 때 k ∈ {6, 10, 14, 18, 22, 26, 30} 중 k < n

- **공통 사례 목록**은 (모델, 세션, k, 생성 seed)로 생성 전에 정한다. 모든 arm이 같은 목록을 쓴다. 동기 미추출·C 불가·토큰 불일치·무효 출력은 조용히 빼지 않고 상태와 함께 기록하고 분모를 보존한다

### 세션 재료와 동기 선택 (고정 규칙)
- 윗선율: 50 ms 안 동시 타건 중 최고음(`coherence_metrics.top_line`)
- 세션 재료: 블록 k 시작 직전 8초의 윗선율(연주된 것)
- 동기: 직전 2블록(k−2, k−1)의 윗선율에서 **IOI가 모두 60–600 ms인 연속 5음** 중 가장 최근 것. 원래 음높이를 그대로 쓴다. 이조나 코드톤 투영은 하지 않는다
  - 시각은 윗선율 클러스터 onset(지표와 같은 기준)을 0초부터 다시 잰다
  - 단선율로 만든다. 각 음은 다음 음 onset에서 끝나고(마지막 음은 블록 k 시작에서 끝남), 최소 20 ms다
  - velocity는 `played_bars`에 없어서 `played.mid`에서 같은 pitch·onset ±5 ms로 맞춘다. 못 맞추면 `velocity_unmatched`(기록, B/C 제외)
- 동기 인코딩(`encode_notes_simple`)이 24토큰을 넘으면 `motif_too_long`이다. 잘라 쓰지 않고 B/C 비교에서 제외한다(기록). 5음 단선율의 최대 토큰 수가 24라서 실제로는 생기지 않는다
- 5음이 없으면 `no_motif`(기록)

### arm (생성 직전 primer, 순서와 길이 고정)
- **A**: [코드 진술] — 현재 런타임과 같다(블록 코드의 `chord_guide_notes_for_duration`, 48토큰 상한)
- **B**: [동기][코드 진술]
- **C**: [섞은 동기][코드 진술]
  - 섞은 동기는 같은 onset·길이·velocity를 쓰고 음정 순서만 바꾼다. 음정 합이 같으므로 첫 음과 끝 음도 같다
  - 서로 다른 음정 순열 전부를 결정적 순서(`crc32("세션:k")` seed로 섞음)로 훑어, 다음을 모두 만족하는 첫 순열을 쓴다
    1. 원래 음정 열과 다르다
    2. 원래 동기와 **음정 3-gram을 하나도 공유하지 않는다**
    3. 모든 음이 21–108이다
  - 만족하는 순열이 없으면 `c_unavailable`(B−C 비교 제외, 기록). 음정이 전부 같은 동기에서만 생긴다(작은 음정 집합 전수 확인)
  - B와 C 동기의 **실제 인코딩 토큰 수가 같은지 검사**한다. 다르면 다시 고르지 않고 `token_mismatch`(B−C 비교 제외, 기록)
- A 대비 비교(B−A)에는 primer 토큰 수 증가 효과가 섞인다. 이 한계를 명시한다. 토큰 수 효과는 B−C로 분리한다
- **C의 한계**: 토큰 수와 리듬이 같아도 모든 혼입이 사라지지 않는다. 가운데 음 3개가 바뀌므로 동기의 음역 폭·윤곽·코드 적합성이 B와 달라진다. B−C 차이에는 이 차이가 섞일 수 있다
  - 보조 기록으로 사례마다 B와 C 동기의 코드톤 수와 음역 폭을 남기고 결과에 함께 적는다
- 세션 재료 8초에는 동기 자체(k−2, k−1)가 들어 있다. 그래서 B의 재등장에는 "방금 넣은 동기의 재출현"이 포함된다. 이것이 이 실험이 묻는 전달이고, 정확 복사는 XR과 복사 플래그로 따로 본다
- 생성 seed는 `gen_seed × 1000 + k`이고 같은 사례의 세 arm이 같은 seed를 쓴다
- 생성 설정(세 arm 동일, 런타임과 같음)
  - temperature 1.0, top-k 32, top-p 0.95, grammar mask, KV 캐시, LoRA 병합
  - 새 토큰 96개, 목표 길이 반 마디
  - 평가는 primer를 뺀 **새 생성 토큰만** 쓴다

### 지표 (새 생성 블록의 윗선율 4음 창 기준)
- 퇴화 창(음정 셋이 모두 0, 같은 음 반복)은 모든 지표에서 뺀다
- **VR (변형 재등장, 주지표)** = 세션 재료의 서로 다른 음정 패턴 중 생성 블록에 **변형**으로 나타난 개수 ÷ 생성 블록의 비퇴화 창 수(반복 포함)
  - 변형: 음정 셋이 같고(이조 허용), 각 IOI 비가 0.75–1.25 안이며, 정확 일치는 아닌 것
  - 같은 패턴을 기계적으로 반복해도 분자는 1번만 늘고 분모는 늘어난다
- **XR (정확 재등장)**: 같은 방식으로, 음높이가 같고 각 IOI 차가 15 ms 이하인 정확 일치
- **IR (음정만 재등장, 보조)**: 음정 셋이 같으면 리듬과 무관하게 센다. 기존 motif reuse와 같은 종류다
- **복사 플래그**: 생성 윗선율에 세션 재료나 주입 동기와 음높이·IOI(±15 ms)가 같은 연속 5음이 있음
- **블록 내 반복률**: 1 − (서로 다른 비퇴화 창 ÷ 비퇴화 창)
- **코드톤**: 블록 코드 기준 생성 음의 코드음 비율
- **유효성**: 런타임 검증(`validate_generated_token_block`, 반 마디, rest 허용)
- 생성 시간

### 분모와 무효 출력 (실행 전 고정)
- 4음 창이 없는 출력(윗선율 4음 미만), 같은 음만 반복하는 출력은 창 수 0이다
- 세션·arm의 비율은 **비율의 합**이다. VR = Σ변형 패턴 수 ÷ Σ창 수. 사례별 비율을 평균하지 않는다
  - Σ창 수가 0이면 그 세션·arm의 VR은 **정의되지 않음**이다
  - 창 수 0인 유효 출력 개수를 arm별로 보고한다
- **무효 출력**은 런타임에서 fallback으로 바뀌어 연주되지 않는다. 그래서 VR·XR·IR·복사·코드톤·반복률에서 뺀다. 유효율 분모에는 남긴다
- 비교별 사례 목록
  - B−A: 동기가 있는 사례(`ok`, `c_unavailable`, `token_mismatch`)
  - B−C: `ok`만
  - 두 arm은 항상 같은 사례 목록에서 잰다
- **판정에서 정의되지 않은 세션은 양수가 아니다.** 비교 가능 사례가 0인 세션, 어느 arm의 VR이 정의되지 않은 세션이 여기에 든다
  - 평균은 정의된 세션으로만 낸다. 정의된 세션이 하나도 없으면 그 기준은 불통과다
- 코드톤·유효율 기준은 B−A 사례 목록으로 잰다. 복사 플래그 비율은 모델마다 B−A 목록의 유효 B 출력 전체에 대한 비율이다

### 집계와 보고
- 모델별로 보고한다. **세션별 평균**(블록·seed 평균)을 먼저 낸다. 이어서 모델 효과는 세션 평균들의 평균과, 세션 중 양수인 개수로 낸다
- 블록과 생성 seed는 같은 세션 안에서 독립 표본이 아니다. 사례 수를 독립 n으로 쓰지 않는다
- 상태별 사례 수(정상, `no_motif`, `motif_too_long`, `c_unavailable`, `token_mismatch`)와 arm별 유효성 분모를 함께 적는다

   - 사후 보정 스크립트도 같은 방식이었다. 창마다 그 창 안의 음으로 윗선율을 만들도록 고쳤다

# Aria 조건 adapter: loss 적용 위치 3팔 대조 (사전 등록)

작성 2026-10-09. 아스트라 결정. 같은 합성 문제(`ARIA_COND_32STEP.md`)에서 loss를 어느 target에 거느냐만 바꾼다. `musically_verified: false`. 학습 산출물은 `synthetic_diagnostic_only`다.

## 질문 (하나)
loss 적용 위치를 바꾸면, 이 합성 문제에서 맞는 구별 음의 절대 질량과 짧은 생성이 달라지는가.

- 최대 결론은 "어떤 loss 위치 변경이 이 합성 문제에서 절대 구별 음 질량과 짧은 생성에 영향을 줬는가"까지다
- C가 나아져도 그것은 "`<E>`를 배우지 못하게 한 합성 제어 probe"일 뿐이다. 제품 loss로 자동 채택하지 않는다. 곡을 끝내는 법이나 원본 표현 보존은 별도 문제다
- 세 팔 모두 실제 음악, 티그랑, 코드 전환은 검증하지 않는다

## 세 팔 (`scripts/aria_cond_synth.py`의 `target_mask`, 시험 `tests/test_aria_cond_synth.py`)
mask는 shift 뒤 target 위치 기준이다. 위치 k의 logits는 toks[k + 1]을 예측한다.

| 팔 | loss를 거는 target |
|---|---|
| A | 전체 next-token(기존 32 step과 같음) |
| B | 첫 구별 음부터 끝까지: 그 음높이, onset, dur, 뒤 코드음, `<E>`. prefix target은 뺀다 |
| C | B에서 `<E>` target만 뺀다. 입력에서 `<E>`를 지우거나 생성에서 막지 않는다 |

- A 대 B는 prefix 재현 loss의 효과, B 대 C는 `<E>` target loss의 효과다
- 다만 각 팔의 loss는 고른 위치의 평균이다. 그래서 gradient 크기와 잡음도 달라진다. 순수한 인과 기전을 완전히 분리했다고 말하지 않는다
- 두 후보만 겨루는 contrastive loss는 넣지 않는다(상대 선호만 키울 위험)

## 고정
- 새 0 초기화 adapter 3개
- 같은 합성 자료(훈련 16, 평가 8), 같은 모델과 주입 위치(16번째 block 입력)
- Adam lr 1e-3, batch 1, 최대 128토큰, 팔마다 정확히 32 step
- 샘플 순서는 세 팔이 같다(`random.Random(0)`, 16예제 × 2회). 평가는 step 0과 32에서만 한다. best 선택은 없다
- 총 96 step 뒤에는 추가 학습을 하지 않는다

## 재현 확인 (판정 전 조건)
- A는 기존 32 step의 재실행이다. step 32의 L(Cmaj7)·L(Cm7)과 E·B / Eb·Bb / `<E>` / C·G 질량이 이전 값(`aria_cond_32step/result.json`, `mass.json`)과 **1e-4 안에서** 같아야 한다
- 다르면 원인을 보고하고 판정을 유보한다

## 측정 (평가 prefix 4개 × 조건 Cmaj7·Cm7, 첫 구별 음 직전, 전체 vocab)
- M: 맞는 구별 pc의 raw 질량(Cmaj7 → E·B, Cm7 → Eb·Bb), 반대 구별 pc 질량, 맞음 − 반대, `<E>`, C·G
- 비교: 각 팔 대 base, 팔 사이의 paired 차이(B − A, C − B)를 경우마다(8경우) 낸다
- 평가 CE: 팔마다 train loss가 다르므로 그 값끼리 직접 비교하지 않는다. 공통 continuation 위치(첫 구별 음부터)로 통일하고, `<E>` 포함과 제외를 둘 다 낸다. 맞는 조건으로 잰다

## 판정 기술 (결과 전 고정, 성공 목표 없음)
- 팔마다: 8경우 중 맞는 조건의 M이 반대 구별 pc 질량보다 큰 경우 수. P(Cmaj7) 4경우와 Q(Cm7) 4경우를 따로 적는다
- 팔 사이: paired 차이의 부호 수(8경우)와 평균
- **부분 결과**로 적는 경우
  - 한쪽 품질만 나아졌다
  - 특정 prefix가 지배한다. 기준: 가장 큰 한 경우가 양의 paired 차이 합의 절반을 넘는다
- `<E>`가 어느 팔·조건에서 늘거나 줄었는지 적는다
- E_first가 1을 넘는지 같은 새 목표는 쓰지 않는다

## 짧은 자유 생성 (정보 항목)
- 세 팔 × 같은 prefix 4개 × 조건 2개 = 24개
- 기존 설정: seed 1을 샘플마다 다시 쓰고, temperature 1, min_p 0, 최대 24토큰, `<E>`에서 멈춘다. 공통 난수 paired 대조로 표기한다. 독립 추출 확률은 계산하지 않는다
- 보고
  - 문법 유효성: `(piano, p, v)` → `onset` → `dur` 순서, 구간 안 onset 비감소
  - 첫 토큰이 `<E>`인지
  - 구별 pc 전량(E·Eb·B·Bb)
- 마스크, 중간값, sweep은 없다

## 안정성과 중단
- base 파라미터와 체크포인트 sha256 불변, 매 step 유한, 저장·재로드 일치
- 중단 조건: 전체 wall 15분, pressure level 4, OOM, 유한하지 않은 값

## 판정 기술 (사전 등록 규칙)
- **세 팔 모두** 맞는 조건의 M이 반대 구별 pc보다 컸다: 8/8, 두 품질 각 4/4
- **loss 위치 변경은 절대 구별 음 질량을 바꿨다.** 평균 M은 base 0.071 → A 0.112 → B 0.199 → C 0.378이다
  - B − A, C − B, C − A 모두 8경우 전부 양수이고 두 품질 각 4/4다
  - 가장 큰 한 경우의 몫은 0.15–0.22라 절반을 넘지 않는다. 사전 기준상 "특정 prefix 지배"나 "한쪽 품질만"인 부분 결과가 아니다
- **`<E>`의 움직임**
  - B는 A보다 Cm7 4경우에서 `<E>`가 크게 늘었다(+0.142 ~ +0.249). Cmaj7 4경우에서는 조금 줄었다(−0.004 ~ −0.038). 평균 `<E>`는 0.122 → 0.212다
  - 원인 후보: prefix target을 빼면 예제당 target이 13개로 줄어, `<E>` target의 비중이 커진다. 확인하지 않았다
  - C는 `<E>` target을 뺐다. 이 위치의 `<E>` 질량이 base 수준(약 0)으로 돌아왔다
- **짧은 생성(정보 항목)**
  - C는 8샘플 모두 맞는 구별 음을 포함했다. Cmaj7은 맞음 15 / 반대 0, Cm7은 맞음 10 / 반대 1이다. 다만 8개 모두 24토큰 상한까지 갔다(이 생성 안에서 `<E>`가 나오지 않음)
  - B는 Cmaj7 4/4에 맞는 구별 음이 있었다. Cm7은 4개 중 3개가 첫 토큰 `<E>`로 바로 끝났다. 위 `<E>` 상승과 맞는 모습이다
  - 공통 난수 대조이고 독립 확률은 계산하지 않는다
- 평가 CE(공통 continuation 위치)
  - `<E>` 제외: A 1.368, B 1.297, C 1.041
  - `<E>` 포함: C가 1.876으로 가장 높다. `<E>`를 배우지 않았기 때문이다

## 해석 범위
- 이 합성 문제에서는 prefix target과 `<E>` target을 loss에서 빼면, 맞는 구별 음의 절대 질량과 짧은 생성의 구별 음이 늘었다
  - 다만 B는 Cm7에서 곧바로 끝내는 쪽으로 기울었다
  - C는 이 학습에서 `<E>` target을 뺐고, 생성 8개가 24토큰 상한까지 갔다. base가 원래 가진 종료 능력이 사라졌다는 증거는 아니다. C는 **"`<E>` target을 뺀 합성 제어 probe"**이며 제품 loss로 채택하지 않는다
  - C의 결과는 인위적으로 짧게 끝나는 fixture의 종료 효과다. 모든 `<E>`를 빼야 한다는 근거가 아니다(아래 후속 결정의 `<E>` 출처 분리 참고)
  - onset 역행 1건은 생성 유효성 한계로 계속 적는다
- 팔마다 target 수와 gradient 크기가 달라 순수한 인과 기전 분리는 아니다
- 남은 한계: C 근음 하나, 평가 prefix 4개, seed 하나, 코드 하나로 고정(전환 없음), 합성 아르페지오. 실제 음악, 티그랑, 코드 전환은 검증하지 않았다. 쌍 음악 자료 부족은 그대로다
- 총 96 step으로 끝냈다. 추가 학습은 하지 않는다. 아스트라 결정대로 합성 튜닝을 반복하지 않고, 다음은 실제 자료 학습 진입 조건으로 돌아간다

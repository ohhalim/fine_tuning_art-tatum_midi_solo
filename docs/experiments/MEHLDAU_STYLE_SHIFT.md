## 질문 순서 (각 실험은 한 질문)

### V1 — 지표가 멜다우와 일반 재즈를 구분하는가
지표: `scripts/style_distance.py`. 여섯 descriptor 히스토그램(음정 간격, IOI, 동시타건 수, 음역, 벨로시티, 음길이)의 평균 JS 거리.

- 멜다우 18곡과, `jazz_full/train`에서 멜다우와 토큰 해시가 겹치는 곡을 뺀 일반 곡을 무작위로 뽑는다(seed 0). 기준용 100곡과 probe용 100곡으로 나눈다
- **1차 판정은 1024토큰 조각 단위다** (생성 길이에 맞춤). 곡마다 결정적 위치의 조각 하나를 쓴다
- 멜다우 probe: 기준 = 나머지 17곡(leave-one-out). 일반 probe: 기준 = 멜다우 18곡 전부
- 정답 조건: 멜다우 probe는 d(멜다우) < d(일반), 일반 probe는 그 반대
- **판정: 균형 정확도 ≥ 0.75면 V2에 사용한다.** 미만이면 V2의 스타일 해석을 하지 않는다
- 특징별 정확도는 탐색용으로만 보고한다. 결과를 보고 특징을 고르지 않는다

### V2 — update를 늘리면 생성이 멜다우 쪽으로 이동하는가 (V1 통과 시)
- 한 연속 run, MPS. `run_mehldau_update_budget_diag.py`와 같은 설정(armB 시작, batch 4, accumulation 4, lr 3e-4, LS 0.1)으로 512 update를 계획한다. snapshot은 0/8/32/128/256/512
- 생성: 중립 primer `outputs/chord_ab/ii_V_I.mid`, seed 8개 × 768토큰 연속 생성, grammar mask, temperature 1.0, top-k 32, top-p 0.95
- 점수: shift = d(일반 기준) − d(멜다우 train 16곡 기준). 높을수록 멜다우 쪽이다
- 복사 위험: 생성 16-gram 중 train 16곡에 정확히 있는 비율
- **판정**
  - 스타일 이동 지지: 어떤 snapshot의 shift가 update 0보다 커야 한다. 차이는 seed 간 부트스트랩 95% 구간이 0을 넘어야 한다
  - 복사 경고: 16-gram 복사율 > 0.10이면 "스타일"보다 "암기"로 기록한다
  - val CE(base가 본 곡)가 update 0보다 나빠지면 과적합 신호로 기록한다
- 들리는 스타일 성공은 이 실험으로 주장하지 않는다

### V1b — 곡 단위 교차검증 분류기 (V1 실패 후 추가, 실행 전 등록)
V1의 최근접 기준 JS 거리가 기준에 미달했다(§결과). 결과를 보고 특징을 고르지 않는다. 같은 여섯 히스토그램을 그대로 쓰고 판별 방법만 바꾼다.

- 입력: 여섯 히스토그램을 각각 정규화해 이어 붙인 119차원 벡터. fold마다 train 통계로 표준화한다
- 표본: 곡당 겹치지 않는 1024토큰 조각. 멜다우는 곡당 최대 8개, 일반 200곡(V1과 같은 표본)은 곡당 최대 2개
- 모델: L2 로지스틱 회귀(numpy, λ=1.0, 클래스 가중치 균형)
- **곡 단위 6-fold.** 같은 곡의 조각은 train과 test에 동시에 들어가지 않는다
- **판정: 조각 단위 균형 정확도 ≥ 0.75면 V2 스타일 점수로 사용한다.** 점수는 생성 조각의 P(멜다우) 평균이다
- 한계(사전 기재): 멜다우 18곡 중 15곡이 한 앨범(Suite - April 2020)이다. 분류기가 연주자가 아니라 앨범·전사 특성을 배울 수 있다. 통과해도 "멜다우 스타일"이 아니라 "이 18곡 코퍼스 쪽"으로만 해석한다

### V2 보강 — 우도 기반 특화도 (V1b 실패 후, V2 결과를 보기 전 등록)
생성 descriptor 지표가 두 번 모두 타당성 기준에 미달했다. 그래서 V2의 1차 질문을 모델 우도로 바꾼다.

- 각 snapshot에서 LS·dropout 없는 CE를 잰다. 대상은 (a) 멜다우 train 16곡 고정 crop, (b) 일반 재즈 probe 100곡(V1 probe 표본, 곡당 가운데 1024토큰)
- 특화도 = ΔCE_멜다우 − ΔCE_일반 (update 0 대비). 음수일수록 멜다우 쪽으로 특화된 것이다
- **판정: 어떤 snapshot에서 특화도 ≤ −0.02이고 ΔCE_일반 ≤ +0.05면 "일반 능력을 크게 잃지 않고 멜다우 코퍼스로 특화"로 기록한다.** ΔCE_일반 > +0.05면 "특화하면서 일반 성능 손실"로 기록한다
- 생성 P(멜다우)·JS shift·16-gram 복사율은 **탐색용 기술값**으로만 보고한다(복사율 경고 기준 0.10은 유지)
- 멜다우 곡은 base 사전학습셋에 있으므로 새 곡 일반화는 여전히 주장하지 않는다

### V2 학습 — 512 update, MPS
`outputs/mehldau_diag/update_budget_v2_mps512/` (LoRA snapshot, 로그). armB 시작, batch 4, accumulation 4, lr 3e-4 → cosine(512 update), LS 0.1, seed 42.

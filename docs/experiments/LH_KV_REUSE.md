# 지금 계약에서 재사용할 수 있는 공통 앞부분 감사 (사전 등록)

작성 2026-10-18 14:2x KST. 이슈 #1793. 아스트라 범위(msg_ff82232b47e4). 계약 변경 없음, 생성·학습·제품 경로 변경 없음, 청취 없음.

## 1. 왜

- #1791(v2): 관측 왼손 문맥을 블록마다 전체 prefill하면 dev 1,314 요청 중 33.4%만 1박 안이었습니다
- 실시간에서 모델은 앞 요청 입력(문맥 + 생성한 오른손)을 KV에 갖고 있습니다. 새 요청 문맥이 그 입력과 앞부분이 같으면, 같은 앞부분 P까지 KV를 두고 그 뒤 S토큰만 다시 계산할 수 있습니다(P 뒤의 옛 KV는 mask로 가립니다)
- 이번에는 **#1773 계약(관측 창 7.5초)을 그대로** 두고, 실제 토큰열에서 P와 S가 얼마나 되는지, 무엇 때문에 앞부분이 갈리는지 감사합니다. "crop 이후 왼손 전부 유지" 같은 계약 변경은 이 결과를 본 뒤 따로 검토합니다

## 2. 질문 (하나)

지금 계약에서 연속 요청의 b 입력은 앞부분을 얼마나 공유하며, 앞부분 재사용으로 계산한 결과가 전체 재계산과 같은가?

## 3. 공통 앞부분 감사 (모델 없음, 실행 전 고정)

- dev 4곡(44, 68, 134, 185), `lh_context.build_request`(계약 기본값)로 b 입력을 다시 만듭니다
- 같은 곡의 연속 요청 k−1 → k(k ≥ 2)마다
  - Pseq = 앞 요청 b 입력 전체(문맥 + continuation), N = 새 요청 b 문맥(`label_start`까지)
  - P = Pseq와 N의 공통 앞부분 길이(토큰 ID 비교), S = len(N) − P
  - crop 상태(keep_from 또는 base_ms)가 바뀌었으면 P = 0(전체 reset)으로 둡니다
- **갈림 원인**(첫 갈림 위치의 실제 토큰·태그로 판정)
  - `crop`: crop 상태가 바뀜
  - `expired`: 갈림 위치에 Pseq 쪽 왼손 음이 있고, 그 음(음높이·onset)이 N에 없음(관측 창에서 빠짐)
  - `insert`: 갈림 위치에 N 쪽 왼손 음이 있고, 그 음이 Pseq에 없음(새로 관측)
  - `held_update`: 같은 왼손 음(음높이·onset)인데 길이 토큰이 다름(앞 요청에서 s로 잘랐던 음이 더 울림)
  - `none`: 갈림 없이 N이 Pseq의 앞부분과 같음
  - `other`: 위에 없는 경우(같은 onset 순서 등). 나오면 사례를 적습니다
- 미래 off는 쓰지 않습니다(계약 L1~L8 그대로)
- 대조: a 입력(오른손만)도 같은 방식으로 셉니다. 오른손 이력은 덧붙기만 하므로 crop 말고는 S가 작아야 정상입니다
- 보고: P·S 분포(중앙값·p90·최대), 원인별 수, a 대조

## 4. 동등성 시험 (MLX, 실행 전 고정)

- 같은 N에 대해 (i) 위치 0부터 전체 prefill, (ii) Pseq를 먼저 prefill한 KV에서 P까지만 두고 N[P:]를 위치 P부터 계산(`max_kv_pos = len(N) − 1`로 그 뒤 옛 KV는 가림). 마지막 위치 logits와 S개 위치 top-1을 비교합니다
- 통과: S개 위치 top-1 모두 같고, 마지막 logits 최대 |차| ≤ 1e-3(#1741 KV smoke와 같은 기준)
- 사례: 합성 fixture(왼손 insert, expired, held_update, 변화 없음, 빈 왼손, 같은 onset) + dev 실제 쌍. dev 쌍은 원인별로 곡 순서에서 처음 나온 것 하나씩(최대 6개)
- **하나라도 실패하면 5절 비용 결론을 내지 않습니다**

## 5. 비용 (MLX, 대표 지점만, 규칙 지금 고정)

- 3절 분포에서 crop이 아닌 쌍의 S 분위 50·90·99와, 각 분위 근처(±10%) 쌍들의 P 중앙값으로 대표 지점 3개를 정합니다. 여기에 (P의 p90, S의 p90) 하나를 더합니다
- 지점마다 T(P, S) = P까지 KV가 있을 때 S토큰 계산 시간(준비 1회 + 5회 중앙값)
- 요청 비용 = T(P, S) + 블록 토큰 n개 생성의 추가 forward n − 1회(#1791 v2와 같은 decode 값). 마감 1박(468.75 ms)과 따로 표시합니다
- 보수적 비율: 측정한 지점 중 마감 안인 것에 대해, P·S가 그 지점 이하인 쌍의 비율(그 지점이 "지배"하는 쌍)
- crop으로 P = 0인 쌍은 #1791 전체 prefill 곡선 값을 씁니다
- 이것은 모형 시퀀스(정답 이력 조건)의 비용이지 자유 생성 성공률이 아닙니다

## 6. 읽는 법

| 관측 | 말할 수 있는 것 | 말하지 않는 것 |
|---|---|---|
| 동등성 통과 + S 작음 + 대부분 마감 안 | 지금 계약 그대로 앞부분 재사용으로 입력 경로를 붙여 볼 근거 | 실시간에서 늘 마감을 지킨다, 왼손 문맥이 음악에 도움이 된다 |
| 동등성 통과 + 앞부분이 거의 안 남음(원인이 expired·held_update 위주) | 그때 "crop 이후 왼손 유지" 계약 비교를 따로 검토. 그 변경도 held 길이 갱신은 없애지 못함 | 계약을 바로 바꾼다 |
| 동등성 실패 | 비용 결론 없음, KV 재사용 구현 점검이 먼저 | — |

# 후보 1개 + carry48 + avoid 벌점: 반복 벌점 스윕과 확인 (사전 등록)

작성 2026-10-03. 이슈 #1662. Claude 혼자 진행한다. 스윕, 선택 규칙, 확인 판정을 모두 실행 전에 고정했다. `musical_quality_verified: false`.

## 근거
- 사용자: 이어 치기 버전도 "아직 불협이 많다"
- avoid 벌점 2.0이 불협을 가장 크게 줄였다(avoid 음 시간 .161 → .02–.03, #1656·#1658·#1660)
- 후보 2개 + carry48 조합은 예산 경계에 있다(p99 374–432 ms, 대체 1회, #1660). 후보 선택은 박 위 clash를 조금 더 낮추는 보조였다
- 반복: avoid 벌점만 쓰면 .175, 생성 단계 반복 벌점 1.5를 더하면 .042지만 블록 안 도약 p90이 17이 된다(#1658). ranker 반복 항은 .134였다(#1660). 실제 비밥은 .055다
- 반복이 이어지는 길이 구성(2연속, 3연속, …)은 실제와 비슷하다. 문제는 전체 빈도다(탐색)
- 같은 단위 안에서 실패를 본 뒤 R을 다시 고르면 사후 튜닝이 된다. 그래서 이번에는 **스윕과 선택 규칙을 먼저 고정하고, 선택에 쓰지 않은 seed로 확인한다**

## 설정
- 공통: `--preset bebop -- --solo-line --comp --comp-style varied --phrase-breath 24 --candidates 1 --context-carry-tokens 48 --context-carry-position after --harmony-bias 2`
- holdout 진행 3개, 16마디, 128 BPM

## 1단계: 선택 (seed 42·43)
- 팔: `--repeat-penalty` R ∈ {0, 0.5, 1.0}
- **선택 규칙(고정):** 같은 음 반복 ≤ .109이고 블록 안 음정 p90 ≤ 12를 동시에 만족하는 가장 작은 R을 고른다. 하나도 없으면 여기서 멈추고 기록한다
- 기준값(.109, 10)은 #1656 bias0 팔이다. 지금 청취 설정(후보 2개, 벌점 없음)의 값이다

## 2단계: 확인 (seed 44·45, 선택에 쓰지 않음)
- 고른 R로 6회 실행한다. #1656 bias0 기준으로 판정한다(1단계 결과로 바꾸지 않는다)
1. avoid 음 시간 ≤ .081(기준의 절반)
2. 컴핑과 동시 충돌 ≤ .085(기준의 0.7배)
3. 박 위 clash ≤ .281(후보 선택이 없어도 기준보다 나빠지면 안 된다)
4. 경계 ≥ 9 비율 ≤ .22, 경계 p50 ≤ 4
5. 같은 음 반복 ≤ .109
6. 블록 안 음정 p90 ≤ 12
7. 시작 음정 고유 비율 ≥ .803, 복사 블록 ≤ .05
8. 초당 음 수와 쉼이 데이터 범위 안
9. 대체 0, miss ≤ 2, invalid 0, p99 ≤ 419 ms
- 통과하면 이 설정을 `fl_live` 권장 조합으로 바꾸고 청취물을 다시 만든다. 미달이면 기록하고 멈춘다(추가 스윕 없음)

# 학습 부족인가, 추론 입력 불일치인가 — 자연 문맥 vs 코드 프라이머 진단 (계획)

작성 2026-10-02. 이슈 #1597. 계획 문서다. 측정 전에 판정 규칙을 고정하고, 독립 리뷰를 받은 뒤 실행한다. **새 학습은 이 진단 결과가 근거를 줄 때만 검토한다.**

## 배경
- 런타임 출력은 앞에서 친 음정 패턴을 다시 쓰지 않는다(VR 0. 실제 Tatum 0.014, 멜다우 0.054, #1575). FL 청취에서도 "무작위적"이었다
- 그런데 기존 학습은 이미 연속 구간을 썼다(`music_transformer/dataset/e_piano.py` 95–108: `x = data[:max_seq]`, `tgt = data[1:]`)
  - 모델은 "자연스러운 앞 문맥 → 다음 토큰"을 이미 배웠다. 그러니 같은 방식으로 다시 학습하는 것을 "연속성을 처음 가르친다"고 부를 수 없다
- 반면 런타임 입력은 학습 때와 다르다
  - 반 마디마다 처음부터 다시 생성한다(블록 리셋)
  - primer는 코드 가이드 음 몇 개뿐이다(코드 프라이머)
  - 이력 모드에서도 이력 뒤에 코드 진술을 끼워 넣는다
- 그래서 원인 후보가 둘이다
  - (가) 모델이 연속성을 충분히 배우지 못했다(학습 부족)
  - (나) 배운 것은 있는데 런타임 입력이 학습 분포와 달라서 쓰지 못한다(추론 입력 불일치)

## 질문 (하나)
같은 처음 보는 곡의 같은 이어지는 구간에 대해, 자연 문맥 조건과 런타임식 조건(코드 프라이머·블록 리셋)이 실제 이어지는 구절의 가능도와 자유 생성의 패턴 재등장을 다르게 만드는가.

## 데이터 (곡 단위 분할 보존, 누출 금지)
| 모델 | 진단용(파이프라인·탐색) | 평가용 |
|---|---|---|
| Tatum 완성 | val12(모델 선택에 쓰여 노출됨) | fresh12(학습·선택에 안 씀, 최종 평가 1회 사용) |
| 공통 base | 위와 같은 곡(base는 Tatum을 보지 않음) | 위와 같음 |
| 멜다우 완성 | 없음 | 재사용 holdout 2곡. 기술 통계로만 보고하고 판정에 쓰지 않음 |

- 곡 목록과 파일 해시를 결과에 기록한다. 학습 manifest와의 교집합이 0인지 확인한다
- 위치: 곡마다 앞 문맥 256토큰 이상이 있는 지점에서 결정적으로 고른다(곡당 최대 8곳, 겹치지 않게)
- 이어지는 구간(target): 그 지점 뒤 실제 음악 2초 분량의 토큰

## 조건 (target은 모두 같음)
| 조건 | primer | 의미 |
|---|---|---|
| N | 실제 앞 문맥 256토큰 | 학습 분포와 같다 |
| N48 | 실제 앞 문맥 마지막 48토큰 | 길이를 코드 프라이머와 맞춘 대조 |
| C | 코드 가이드 48토큰 | 지금 런타임(블록 리셋 + 코드 프라이머) |
| NC | 실제 앞 문맥 + 코드 가이드(이력 모드 순서) | 코드 진술 삽입 효과 |
| M | 다른 곡의 앞 문맥 256토큰 | 앞 문맥이 그 곡이라서 도움이 되는지 확인하는 대조 |

- 코드 가이드는 처음 보는 곡에 코드 라벨이 없다. 그래서 target 구간 음들의 pitch class로 템플릿을 맞춘 **오라클 추정 코드**를 쓴다
  - C 조건에 유리한 쪽이다. 그래도 C가 N보다 나쁘면 결론은 보수적이다
  - 추정 규칙은 `live_chords.recognize`의 템플릿을 쓴다. 맞는 것이 없으면 그 위치는 기록하고 C/NC에서 뺀다(분모 보존)

## 측정
1. **target 가능도(teacher forcing):** target 토큰당 평균 NLL
   - 앞 문맥 효과: NLL(M) − NLL(N). 양수면 그 곡의 앞 문맥이 이어지는 구절 예측을 돕는다
   - 입력 불일치: NLL(C) − NLL(N), NLL(NC) − NLL(N), NLL(N48) − NLL(N)
2. **자유 생성(free rollout):** 각 조건에서 target 길이만큼 생성한다
   - 실제 앞 8초 윗선율 대비 VR/XR/IR(#1575 지표, 창별 윗선율)
   - 실제 이어지는 구간의 같은 지표를 기준으로 함께 적는다
   - 동기 지표 하나만 최대화하지 않는다. 코드톤(오라클 코드), 음 수, 검증 통과율도 함께 적는다
- 집계: 곡별 평균을 먼저 낸다. 곡 단위 bootstrap 95% CI를 쓴다. 위치를 독립 n으로 세지 않는다

## 판정 규칙 (평가용 fresh12, Tatum과 base 각각, 실행 전 고정)
- **(나) 추론 입력 불일치 지지:** 다음을 모두 충족
  - NLL(M) − NLL(N)의 CI가 0보다 크다(앞 문맥이 쓰인다)
  - NLL(C) − NLL(N)의 CI가 0보다 크다
  - 자유 생성 VR이 N에서 C보다 높다(곡별 평균의 차이 CI > 0)
  - → 다음 단계: 런타임에 실제 연주 이력을 학습 분포에 가깝게 넣는 방법을 먼저 고친다. 새 학습은 보류
- **(가) 학습 부족 지지:** NLL(M) − NLL(N)의 CI가 0을 포함하고, N에서도 자유 생성 VR이 실제 이어지는 구간보다 뚜렷이 낮다
  - → 새 로컬 소규모 학습 실험을 설계할 근거가 된다(별도 이슈, 별도 사전 등록)
- **둘 다 아니면** 결론 보류로 기록한다. 이 단위에서 조건이나 판정 기준을 다시 탐색하지 않는다
- 진단용(val12)에서는 파이프라인과 분포만 확인한다. 판정은 평가용에서만 한다

## 예산과 범위
- 로컬 CPU만 쓴다. 새 데이터·새 학습·외부 업로드·유료 자원은 쓰지 않는다. 기존 체크포인트는 읽기만 한다
- 평가용 기준: 모델 2개 × 12곡 × 최대 8위치 × 조건 5개
  - 가능도 계산 최대 960회
  - 자유 생성은 조건 4개(N, N48, C, NC)에서 위치당 seed 2개, 최대 1,536회
- 품질·스타일 주장은 하지 않는다(`musical_quality_verified: false`)

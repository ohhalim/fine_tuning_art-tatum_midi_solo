# CPU 부하에서 프리셋 설정의 실시간 여유 — 사전 등록

작성 2026-09-29. 이슈 #1534. `style_verified: false` · `musical_quality_verified: false` · 가상 CoreMIDI 포트, 합성 부하

**이 절은 실행 전에 작성했다.**

## 질문
프리셋 설정(반 마디 블록, 늦은 fetch, 시작 예산 0.5블록)은 생성 예산을 블록마다 약 0.47초(128 BPM)나 0.25초(240 BPM)로 줄였다. 실제 연주에서는 DAW와 신스가 CPU를 같이 쓴다. 다른 부하가 있을 때도 fallback과 미스 없이 버티는가?

## 조건
- 모델: Tatum 완성. 가장 느린 모델로, 블록 생성 p95가 128 BPM에서 315 ms다
- 런타임: `--chord-primer --chord-blocks-per-bar 2 --half-bar-blocks`(프리셋과 같음), 16마디, `--capture`, `FORCE_CPU=1`
- 부하: `yes > /dev/null` 프로세스 N개(M1 Max 성능 코어 8 + 효율 코어 2)
  - N = 0(같은 세션 기준선) / 4 / 8
  - 부하는 각 N 구간 동안 계속 돌고, 구간이 끝나면 PID로 종료한다
- 128 / 240 BPM × seed 42/43/44. N마다 6회, 총 18회

## 기록과 판정 (측정 목적, 기본값 결정 없음)
- 부하·템포 조건마다 3회 모두 fallback 0 · 오류 0 · 미스 0이면 **성립**이다
- 블록 생성 p95/블록 길이 비율과 스케줄러 지각 최대를 함께 보고한다
- 성립하지 않는 부하가 있으면, 그 조건의 fallback이 생성 지연 때문인지(`fallback_not_ready`) 기록한다
- 해석 한계: `yes`는 CPU 정수 부하일 뿐이다. DAW의 오디오 스레드 우선순위, 메모리 대역, GPU 사용과는 다르다

- 관측: 부하가 있을 때 스케줄러 지각 꼬리가 오히려 작았다(N = 2·4에서 최대 5–7 ms, 부하 없을 때 7–16 ms). 코어가 깨어 있는 상태가 유지되기 때문으로 보인다(원인 검증 안 함)

## 후속 — 무거운 부하에서 시작 예산을 끄면 버티는가 (사전 등록, 실행 전)
- 조건: N = 8(실제로 8개, 루프 수정), 위와 같은 설정에 `--start-budget-bars off`를 더한다(블록 fetch 직후 생성 시작, 예산 약 1블록). 128 / 240 BPM × seed 42/43/44
- **판정:** 템포마다 3회 모두 fallback 0 · 미스 0이면 "무거운 부하에서는 `--start-budget-bars off` 권장"으로 문서화한다. 아니면 "성능 코어를 모두 쓰는 부하에서는 성립하지 않음"으로 기록한다

### 후속 결과 — 기준 미달, 그러나 fallback이 크게 준다
원시값: `docs/experiments/load_margin/load8_budget_off_sweep_report.json`. 부하 8개가 실제로 돌았다(PID 8개 확인).

| 설정 (N = 8) | BPM | fallback 블록 (seed 42/43/44, 32블록 중) | 미스 | 블록 생성 p95 ms |
|---|---|---|---|---|
| 시작 예산 0.5(프리셋) | 128 | 9 / 8 / 5 | 0 / 1 / 0 | 768 / 780 / 880 |
| **시작 예산 off** | 128 | **0 / 0 / 1** | 0 / 0 / 0 | 750 / 777 / 812 |
| 시작 예산 0.5(프리셋) | 240 | 4 / 7 / 9 | 0 / 13 / 1 | 376 / 440 / 417 |
| **시작 예산 off** | 240 | **1 / 0 / 1** | 0 / 0 / 0 | 419 / 411 / 451 |

- 사전 기준(3회 모두 fallback 0)에는 미달이다 → **"성능 코어를 모두 쓰는 부하에서는 성립하지 않음"**으로 기록한다
- 다만 시작 예산을 끄면 fallback이 블록의 16–28%에서 0–3%로 줄고, 미스도 없어진다
- 실용 지침(판정 아님)
  - 다른 프로그램이 CPU를 많이 쓰면 `--start-budget-bars off`를 준다(`play_personalized.py ... -- --start-budget-bars off`)
  - 대가로 입력 반영이 약 0.5블록 늦어진다

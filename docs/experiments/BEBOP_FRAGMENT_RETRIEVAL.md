작성 2026-10-17. 이슈 #1782. 아스트라 msg_d589c65d4e5a(설계 결함 지적), msg_c0143040836d(범위 확정). 학습 없음, 새 감사 없음. `quality_claimed: false`.

**모델 생성·개인화 결과가 아닙니다.** 실제 연주 조각을 꺼내 듣는 기준선입니다.

## 1. 질문 (하나)

코드 조건에 맞춰 고른 실제 비밥 피아노 조각이, 원형 그대로도 원하는 릭으로 들리는가?

- 8마디 연결, 이어붙이기, 제품 방식 확정은 이 단위에서 하지 않습니다. 원형 조각이 원하는 릭으로 들릴 때만 연결 단계를 따로 설계합니다
- 선호가 낮아도 "원곡·연주자 자체가 싫다", "모든 검색 방식이 실패했다"로 넓히지 않습니다

## 2. 목표 (고정)

128 BPM 기준 3.75초 두 구간. CMT·#1780과 같은 P 진행에서 골랐습니다.

| 목표 | 코드 | 목표 근음 | 목표 전환 시각 |
|---|---|---|---|
| `change` | Gm7 → C7 | G | 시작 + 1.875초 |
| `hold` | Fmaj7 (3.75초 지속) | F | 없음 |

- 원곡에는 박·마디 정보가 없습니다. 그래서 산출물은 "2마디"가 아니라 "3.75초 조각"이라고 부릅니다

## 3. 입력

- bank: `data/bebop_rh/manifest.json`(#1616)의 train 189곡, 비밥 피아니스트 13명. manifest는 저장소 밖 로컬 파일이며 sha256을 보고서에 적습니다
- 곡마다 manifest의 원 MIDI 경로를 읽고, 파일 sha1이 manifest와 같은지 확인합니다. 다르면 그 곡을 빼고 기록합니다
- 음 ID: `i{악기 번호}_n{그 악기 안 음 번호}`(원 MIDI 순서)

## 4. 추출과 라벨 (LABEL_AUDIT v1 재사용)

- 최고음역 선율 대리: `inference.control.solo_line.top_notes`(50 ms 묶음 최고음) 중 G3(55) 이상. 이 함수는 끝을 다음 onset으로 자르고 최소 10 ms로 늘리므로, **음 선택(ID)에만 씁니다.** 산출 음은 원 MIDI ID의 start·end·velocity로 되돌립니다. 이름은 "오른손 정답"이 아니라 "최고음역 선율 대리"입니다
- 프레이즈: `lick_bank.runs`(0.25초 넘는 쉼으로 끊음) 중 8음 이상. 조각 시작 t0 = 프레이즈 첫 음
- 반주: 선율 대리에 들지 않은 음 중 E4(64) 아래
- 라벨: `scripts/label_audit.py`의 `clusters`·`Sounding`·`phrase_slice`·`slice_at`와 `chord_label.classify`를 그대로 씁니다(v1). v1은 **후보 제안에만** 씁니다
  - v1 한계는 그대로입니다: 수작업 정확도 0.71–0.83 미입증, 미래 묶음(A), 끝난 음 잔존(B), span이 실제 지속이 아님(C). v2는 실행된 적이 없습니다
  - 그래서 매치는 "v1 동시 화음 proxy 일치 후보"라고만 부릅니다. 정확한 코드 매칭이라고 하지 않습니다

## 5. 매치 규칙

- 반박 슬라이스: t0 뒤 반주 묶음의 v1 라벨이 현재 라벨과 다르거나, ambiguous인데 후보에 현재 라벨이 없는 것(label_audit span 규칙). unknown은 반박이 아니라 **미검증**이며 개수와 시간 비율을 적습니다
- `hold`: t0 라벨이 (r, maj7)이고 clear 또는 bass_resolved. [t0, t0 + 3.75) 안에 반박 슬라이스가 없음
- `change`: t0 라벨이 (r, m7)이고 clear 또는 bass_resolved. 첫 반박 슬라이스 tc의 라벨이 (r + 5, 7)이고 clear 또는 bass_resolved. |tc − (t0 + 1.875)| ≤ 0.469초(128 BPM 1박). tc부터 t0 + 3.75까지 새 라벨의 반박 없음
  - 0.469초는 후보 검색 허용 오차일 뿐입니다. 실제 tc, 목표 tc, 차이를 공개하고, 박·코드 전환 정렬에 성공했다고 하지 않습니다. 시간을 늘리거나 당기지 않습니다
- 이조 k: 목표 근음까지의 signed 최소 이동, −6…+5(±6 동률은 −6). 조각 전체에 하나만 씁니다
- 이조 후 MIDI 범위(0–127)를 벗어나면 부적격입니다(음높이 clamp 없음)
- 순위: clear 라벨 수(많은 순) → |k| → |tc 오차|(change만) → 곡 sha1 → t0. **top1만** 꺼냅니다
- 후보가 없으면 `no_match`. 임계값 완화·bank 확대·다른 곡 강제 조건 없음

## 6. 선택 뒤 검증 (선택된 2개만)

- t0 + 30 ms와 tc + 30 ms(change)에 실제로 울리는 원 음(start ≤ t < end)의 ID·pitch class를 따로 출력합니다
- t0 검증: v1이 쓴 슬라이스 음높이류 집합과 t0 + 30 ms의 실제 반주 음높이류 집합이 같아야 합니다. 다르면 `proxy_invalid`(미래 묶음 혼입이나 끝난 음 잔존). tc는 묶음 시작 시각이라 같은 정의로 출력만 합니다
- `proxy_invalid`면 차순위를 다시 고르지 않습니다. bank 전체를 새 기준으로 재감사하지 않습니다. `no_match`·`proxy_invalid`도 이 단위의 유효한 결론입니다

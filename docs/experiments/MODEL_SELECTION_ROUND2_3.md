## 결론 (2026-10-04)
- **"최신 모델을 쓰지 말고 더 찾지 말자"가 결론이 아니다.**
- 작은 모델(13.4M, BebopNet, CMT), 규칙 수정, 반주 교정만으로는 사용자가 만족하는 소리를 얻지 못했다(청취 판정 "그나마").
- 큰 MIDI 모델(Aria, AMT, Moonbeam)을 직접 돌려 보지 않고 뒤로 미룬 것은 Claude와 아스트라의 판단 한계였다. 그래서 다음 실험은 큰 피아노 모델 Aria를 직접 돌리는 T3다.
- **오디오 모델(Suno, Magenta RealTime):** 지금 구조(FL 키보드 → MIDI → Serum)에 직접 맞지 않아 이번 구현 후보에서 뺐다.
  - 출력이 소리라 Serum으로 보낼 수 없고, 음 단위 코드 제어와 검사를 할 수 없다
  - 모델이 열등하거나 실시간이 불가능하다고 판정한 것은 아니다. Suno의 최신 기능과 가격은 검증하지 않았다
- **리서치는 끝나지 않았다.** 매 조사마다 놓친 후보가 나왔다. 다만 Aria를 확인하는 한 단위 동안은 후보 목록을 늘리지 않는다.

## 3차 조사: 주장과 검증
- **새로 승격:**
  - MelodyT5: 113M, ABC 표기, melodization = chord→melody 과제. ✅ MIT, HF 가중치 공개 확인
  - Impro-Visor식 relative-pitch grammar
  - SCG(규칙 유도 diffusion, 철학만 차용)
  - CMT + MINGUS를 섞은 소형 명시 코드 student
  - 대형 teacher(MelodyT5, Moonbeam) → 소형 student 증류
- **강등·정정:**
  - FGG: 주 과제가 반주 생성
  - Function Alignment: 어댑터만 작고 backbone은 12층 768차원. chord→melody 학습은 Nottingham 1,020곡이고 16분 격자다
  - Notochord: 10 ms는 이벤트 응답
  - MuseBarControl: 4090에서 분 단위라 제외
- **"CMT = K-pop 원형" 주장은 근거를 못 찾았다.** 원 CMT 구현 README에는 데이터셋 표기가 없다
- **우리 이력과 겹친 제안:**
  - 박 인지 화성 제약 디코딩(C): 이미 해 봤고(harmony bias, CleanHarmony, 하드 스케일 마스크, 박 인지 realizer) 사용자 청취에서 기각됐다
    - 다만 "화성 제약 전체가 기각됐다"는 과장이다(아스트라). 실패한 것은 특정 모델과 설정이다
  - 코드 상대 retrieval(F): 음을 다시 고르는 릭 묶음(L1–L3)은 기각됐다. 원 pitch를 그대로 이조하는 retrieval은 아직 하지 않았다
  - Impro-Visor식 grammar는 우리 phrase realizer가 이미 본뜬 방식이라 기대 정보량이 낮다. 다만 학습된 grammar와 손으로 쓴 realizer는 같지 않다
- **3차 조사 1순위 "13.4M + 명시 코드 side-channel(B)"**: 진짜 새 가설이다. 하지만 학습할 코드 라벨이 필요하다. 우리 데이터에는 원곡 박, 다음 코드, 전환 시각이 없어서, 첫 B는 현재 코드만 쓸 수 있다

## 아스트라와 정한 것
- **#177** T1 → T2 단계적 축소. 6팔은 같은 질문의 다중 비교라 원칙 위반은 아니다(Claude의 "원칙 위반" 주장 정정). 축소 이유는 실행 조건을 맞추는 비용이다. HSE 비교 파이프라인 코드는 라이선스 표기가 없어 복사하지 않는다
- **#179** 새 모델 목록 확장 중단
  - T1과 작은 U2를 먼저 하고, 결과를 보고 B·D/E·F 중 하나만 고른다
  - U2는 실제 음악 품질이나 정확한 코드 라벨을 주장할 학습 실험의 데이터 선행 조건이다. 공개 모델 zero-shot의 선행 조건은 아니다(Claude 주장 정정)
  - Moonbeam 보류는 우선순위 문제다. teacher로 먼저 쓰는 것에도 반대
- **#181** U2 v1은 "coverage 충족, 정확도 미입증"으로 닫는다. 측정 한계 A–D가 있다(미래 묶음 참조, 끝난 음 잔존, 지속 지표 의미, 시작 기준 coverage). v2는 한 번만 허용한다
- **#182** T1 해석 한계
  - 사후 시작 마디는 "탐색"이다
  - 청취 구간에 CMT의 시작 프레이즈가 포함됐다
  - 2×2 표에 분모를 함께 적는다
  - 스케일 판정 기준(회피음 제외 스케일)을 밝힌다
  - 스윙 렌더 차이와 렌더 해시를 기록한다
  - MINGUS는 blocked: 구현이 WJazzD 원본으로 어휘를 재생성한다
- **#184** 다음 단위 C1(같은 솔로 + 반주만 변경)
  - 코드 구성음 안에서만 보이싱을 바꾸고, 도미넌트는 3·7을 유지한다
  - 불변 검증을 한다
  - 사용자 질문은 자유 서술로 받는다
- **#185** C1 마디 판정 버그
  - 초 단위 허용 오차는 경계 직전 앤티시페이션을 다음 마디로 끈다. MIDI 틱 기준으로 고쳤다(#1679)
  - 남은 C7 위 F는 해결되는 경과 텐션이다. 솔로 오류 판정이 아니다

## 다음: T3 Aria zero-shot (아스트라 #187 계약)
- **질문:** 연주된 짧은 피아노 프라이머를 이어 쓴 출력에, 원하는 비밥 프레이즈와 릭이 있는가. 음악 어휘만 확인한다. 코드 제어, 개인화, 실시간 연결은 별도로 검증한다
- **모델:** EleutherAI Aria(ISMIR 2025)
  - LLaMA 3.2 1B 구조, 전사된 솔로 피아노 약 6만 시간
  - 코드·모델 Apache-2.0. 학습 데이터 조건은 따로 확인한다
  - 생성용 체크포인트는 HF `loubb/aria-medium-base`의 `model-gen.safetensors`(약 2.6 GB). `aria-medium-gen` 저장소는 401로 접근이 안 됐다
  - 데모 전용 체크포인트와 섞지 않는다
- **계약:**
  - A. 체크포인트, revision, tokenizer, backend를 고정한다. 공식 MLX continuation을 그대로 쓴다
  - B. 보유 MIDI의 고정 2–4마디를 프라이머로 쓴다. 미래 정답 음은 주지 않는다. 코드 조건 입력은 지원하지 않으므로 "입력하지 않음"으로 적는다
    - Aria는 이어 치기 모델이다. 왼손 8마디를 주면 그 다음 시간을 이어 칠 뿐, 같은 시간의 오른손을 채운다는 보장이 없다. 이 차이를 모델 성능 실패로 해석하지 않는다
  - C. 양손 원본 출력을 먼저 듣고 보존한다. 오른손 추출과 고정 반주는 별도 진단이다. BebopNet과의 비교는 출력 역할이 다른 제품 선호 비교다
  - D. 프롬프트, 샘플러, seed를 고정하고 전량을 보고한다. 제공한 프라이머와 생성 부분을 분리한다. 지원하지 않는 미래 코드에 대해 실패 판정하지 않는다
  - E. 지연은 로딩, cold compile, prefill, 첫 음, 0.9375초 블록 완성을 나눠서 잰다. 첫 토큰 200 ms와 블록 p99는 같은 것이 아니다
  - F. 원본 MIDI의 표현(페달, velocity)을 유지한 버전을 주 기준으로 삼는다. velocity 평탄화나 강제 스윙으로 표현을 지우지 않는다
- **승인 대기:** 가중치 약 2.6 GB, Aria 코드 저장소, MLX를 별도 환경에 설치

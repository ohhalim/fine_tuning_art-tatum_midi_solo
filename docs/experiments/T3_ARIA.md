## 질문 (하나)
**연주된 짧은 비밥 피아노 프라이머를 Aria가 이어 칠 때, 그 출력에 피아노 비밥다운 프레이즈와 릭이 있는가.**

- 음악 어휘만 확인한다. 코드 제어, 개인화, 실시간 연결은 이번 범위가 아니다
- Aria는 코드 조건 입력을 지원하지 않으므로 코드는 **입력하지 않는다**. 지원하지 않는 미래 코드에 대해 실패 판정을 하지 않는다
- Aria는 이어 치기 모델이다. 같은 시간의 오른손을 채우는 모델이 아니다

## 모델 (A)
- EleutherAI Aria(ISMIR 2025, 코드·모델 Apache-2.0), 공식 저장소 `EleutherAI/aria`의 CLI `aria generate`, backend `mlx`
- 체크포인트: HF `loubb/aria-medium-base`의 `model-gen.safetensors`(생성용 미세조정). `aria-medium-gen` 저장소는 401로 접근이 안 됐다
  - base(`model.safetensors`)와 데모용(`model-demo.safetensors`)은 쓰지 않는다
- 저장소 밖 `/Users/ohhalim/git_box/t3_aria`에 별도 환경으로 설치한다. revision(커밋)과 가중치 sha256은 결과에 기록한다

## 프라이머 (B, 생성 전에 고정)
- **P1(양성 대조):** Aria 공식 예시 `example-prompts/pokey_jazz.mid`. 저자가 잘 연주된 입력으로 제공한 파일이라, 설치와 사용이 맞는지 확인하는 용도다
- **P2, P3(우리 데이터):** `data/bebop_rh` test split에서 오른손 초당 음 수가 가장 높은 두 곡을 쓴다. 발라드가 아닌 빠른 라인을 보기 위해서다
  - P2: Harold Mabern "Joy Spring"(6.08음/초)
  - P3: Kenny Barron "Bud-Like"(5.50음/초)
  - 정정(생성 전): 처음 문서에는 P2 = Bud-Like, P3 = Mabern "Blues in FT-Bone Steak"(5.21)로 적었다. 연주자별 첫 곡만 보고 옮겨 적은 실수다. 규칙("초당 음 수 상위 2곡")대로 뽑으면 위 두 곡이다. 출력을 보기 전에 고쳤다
  - 원 MIDI 양손 그대로 60.0–68.0초 구간을 잘라 0초로 옮긴다. 라이브 녹음의 도입부를 피하려고 60초부터 잡았다
  - 원 MIDI에는 페달(CC) 이벤트가 없다(PiJAMA 전사). 프라이머에도 없다
- 프라이머 길이는 셋 다 8초(`--prompt_duration 8`). 미래 정답 음은 주지 않는다

## 생성 (D)
- 공식 README 예시 샘플러: `--temp 0.98 --min_p 0.035`
- 프라이머마다 `--variations 2`. 6개 전부 보고한다. 좋은 것만 고르지 않는다
- 길이: `--length 1024`(변형당 생성 토큰 수, 약 30초 분량으로 추정). README 예시는 2048이다. 청취 부담 때문에 1024로 정했고, 결과를 본 뒤 바꾸지 않는다
- seed: CLI에 seed 옵션이 없다. 변형은 재현되지 않는다. 그래서 출력 MIDI 자체를 보존한다

## 출력과 청취 (C, F)
- **양손 원본 출력이 주 청취물이다.** 페달, velocity, 타이밍 표현을 그대로 둔다
  - velocity 평탄화, 강제 스윙, 오른손만 추출, 반주 덧붙이기는 하지 않는다
- 렌더러는 지금까지와 같은 피아노다
- 클립마다 제공한 프라이머(앞 8초)와 생성 부분을 구분해서 표시한다
- 올리기 전에 생성 부분을 음 단위로 덤프해 읽는다. 보는 것: 밀도, 음역, 양손 분포, 같은 음 반복, 프레이즈 길이
- BebopNet·CMT와는 출력 역할(양손 대 단선율)이 달라서, 비교는 제품 선호일 뿐 구조 우열이 아니다

## 지연 (E, 이번에는 대략만)
- 모델 로딩 시간, 생성 토큰/초, 음악 1초를 만드는 데 걸리는 계산 시간만 잰다
- 블록 단위(0.9375초) p99, 첫 음 지연, prefill 분리는 품질 가망이 확인된 뒤 별도로 잰다. 첫 토큰 시간과 블록 p99는 같은 것이 아니다

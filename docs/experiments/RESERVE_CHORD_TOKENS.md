# 코드 토큰 예약 — 촘촘한 입력에서 코드 진술 보존 (사전 등록)

작성 2026-09-29. 이슈 #1553. `style_verified: false` · `musical_quality_verified: false` · 가상 CoreMIDI 포트

**이 절은 측정 전에 작성했다.** 구현은 측정 전에 끝냈다.

## 문제 (#1550 후속)
입력 음 16개면 코드 primer가 72토큰이 된다. 이를 48토큰으로 자를 때 최신 토큰을 남기므로 코드 guide 음이 0/4만 남는다.

## 변경 (opt-in, 통과 시 기본값)
- `--reserve-chord-tokens`: 입력이 있을 때 primer = [최신 입력, 예산은 48 − 코드 토큰] + [코드 진술 전체]
- 코드 진술을 생성 바로 앞에 둔다. §6–8에서 문맥을 생성 바로 앞에 두면 코드톤 비율이 떨어졌기 때문이다
- 입력이 없으면 기존과 같은 코드 경로다(출력 동일)

## 측정
- #1550과 같은 조건: Tatum 완성, 반 마디 블록, 128 BPM, 16마디, seed 42/43/44, 16음 입력
- 기준 arm: #1550 실행(`outputs/density_follow/seed*`)

## 판정 (모두 충족하면 기본값을 on으로 한다)
1. 3회 모두 fallback 0
2. 입력이 든 블록의 출력 코드톤 비율(`block_metrics`)이 기준 arm보다 높은 seed가 3개 중 2개 이상이다
3. 입력이 없는 블록은 무입력 실행(#1532)과 전부 동일하다
- 출력 음 수 변화도 보고한다(판정 없음)

# Aria 조건 adapter: 합성 대조 32 step — 조건을 구별해서 쓰는가 (사전 등록)

작성 2026-10-09. 아스트라 결정. 실제 악보·티그랑 학습은 계속 보류한다. `musically_verified: false`. 학습 산출물은 `synthetic_diagnostic_only`이며 corpus나 모델로 배포하지 않는다.

## 질문 (하나)
모델 입력 prefix가 완전히 같고 코드 조건만 다를 때, 32 step 학습한 작은 adapter가 그 조건에 따라 첫 구별 음(3도 또는 7도)의 선호를 바꾸는가.

- 통과해도 말할 수 있는 것은 "같은 prefix에서 외부 코드 조건을 쓰도록 작은 모듈을 학습할 수 있다"까지다. 실제 음악, 코드 전환, 다른 조, 스타일 일반화는 확인하지 않는다
- 이 시험은 배선에서 제어로 한 단계 나아간 검증이다. 쌍 음악 자료가 부족한 문제를 풀지 않는다

## 조건 시각 한계와 이번 범위
- 토큰 순서가 음높이 → onset이므로, 코드가 바뀐 뒤 첫 음의 음높이를 예측하는 위치는 이전 코드를 받는다(`ARIA_COND_SMOKE.md`에 적음)
- 이번에는 **시퀀스마다 코드 하나만** 쓴다. 그래서 이 지연은 시험에 들어오지 않는다. 전환 시험과 onset 기준 조건 설계는 후속이다

## 합성 자료 (`scripts/aria_cond_synth.py`, 시험 `tests/test_aria_cond_synth.py`)
- 고정 생성기로 만든다. 실제 곡을 인용하지 않는다. 코드 계획(Cmaj7 = P, Cm7 = Q)을 먼저 정하고 짝을 만든다
- prefix는 두 코드에 공통인 C와 G만 쓴다. 그래서 P와 Q의 prefix 토큰이 완전히 같다
- prefix 다음 첫 음이 처음으로 코드를 구별하는 음이다: 3도(E / Eb) 또는 7도(B / Bb). 그 뒤 코드음 3개가 이어진다
- family: 훈련 8개(F0–F7) × P/Q = 16예제, 평가 4개(E8–E11) × P/Q = 8예제
  - 음정열·onset 간격·구별 음 종류로 만든 이조 불변 서명이 두 분할 사이에 겹치지 않는다(시험으로 확인)
- 근음은 C 하나다. 다른 조로의 일반화는 주장하지 않는다
- velocity는 80 하나이고, 시퀀스는 5초 안에 끝나 `<T>`가 없다

## 고정 설정
- smoke와 같은 모델, 같은 주입 위치(16번째 block 입력), `Linear(12 → 1536, bias 없음)`
- **새로 0으로 초기화한다.** smoke adapter는 다시 쓰지 않는다
- batch 1, 시퀀스 최대 128토큰, Adam lr 1e-3, eval 모드
- **정확히 32 step**: 훈련 16예제를 두 번 돈다. 매 회 순서는 `random.Random(0)`으로 고정해 섞는다
- loss는 예제 전체 위치의 next-token CE다
- 평가는 step 0과 step 32에서만 한다. 중간 best 선택, 예산 증가, sweep은 없다

## 측정 (결과 전 고정)
- 위치: prefix 마지막 토큰(dur), 즉 첫 구별 음 토큰 바로 앞. teacher forcing이다
- 후보: 같은 velocity의 `(piano, P음, 80)`과 `(piano, Q음, 80)`. 뒤 토큰이 정답 코드를 드러내는 효과는 이 위치에 들어오지 않는다
- L(x, c) = log p(P음 | x, c) − log p(Q음 | x, c)
- 조건 4가지
  - base(adapter 없음)
  - 학습 adapter + 맞는 조건
  - 같은 adapter + 반대 조건
  - 같은 adapter + 0 벡터. bias가 없으므로 구조상 base와 같다. 수치로 확인한다
- 평가 예제마다(8개) 다음을 보고한다
  - LO_맞음: 맞는 조건에서 정답 음의 log-odds. P는 L(x, Cmaj7), Q는 −L(x, Cm7)
  - LO_틀림: 같은 음을 반대 조건에서 잰 값
  - 짝마다(4개) Δ = L(x, Cmaj7) − L(x, Cm7)
  - 주의: P와 Q는 prefix가 같다. 그래서 "LO_맞음 > LO_틀림"은 P와 Q에서 같은 부등식(Δ > 0)이다. 독립 관측은 4짝이다

## 판정 (step 32, 결과 전 고정)
- **조건 사용 증거(통과):** 두 가지를 모두 만족한다
  - 4짝 모두 Δ > 0
  - 8예제 모두 LO_맞음 > 0. 즉 맞는 조건에서 정답 음을 고른다. 이는 P와 Q 양쪽 품질 모두에서, 조건을 바꾸면 선호 방향이 뒤집힌다는 뜻이다
- **부분:** 4짝 모두 Δ > 0이지만 LO_맞음 > 0이 일부(예: 한 품질)에서만 성립한다. 또는 Δ > 0이 일부 짝에서만 성립한다
- **실패:** 어느 짝에서도 Δ > 0이 아니다
- 평균 CE 감소만으로는 성공이 아니다. step 0에서는 adapter가 0이므로 모든 조건이 base와 같다. base가 어느 음을 선호하는지 기록한다

## 짧은 자유 생성 (정보 항목)
- 평가 prefix 4개 × 조건 2개(Cmaj7, Cm7) = 8개
- 샘플마다 seed 1로 같은 난수를 쓴다. temperature 1.0 그대로 softmax에서 뽑는다. 최대 24토큰이며 `<E>`에서 멈춘다
- 음높이 마스크와 후처리는 없다
- 보고: 첫 생성 음, 생성 음 중 E·Eb·B·Bb 수. teacher forcing 통과와 생성 제어는 다른 것이다. 합성 아르페지오라 음악 품질 평가가 아니다

## 안전 확인과 중단
- step 0에서 0 adapter = base(같은 `no_grad` 모드, 차이 0.0)
- 매 step loss가 유한해야 한다
- base 파라미터 바이트와 체크포인트 파일의 sha256이 전후로 같아야 한다
- 저장·재로드 뒤 logits가 같아야 한다
- 중단 조건: wall 15분, pressure level 4, OOM, 유한하지 않은 값. 32 step을 넘겨 loss를 더 줄이지 않는다
- 실패하면 상한 안에서 원인 후보와 첫 음 조건 분리만 보고한다. 층이나 LoRA 탐색으로 바로 넓히지 않는다

## 결과 (`aria_cond_32step/result.json`, 원자료 `/Users/ohhalim/git_box/t3_aria/cond_32step/`)
**판정(사전 등록 기준): 통과.** 4짝 모두 Δ > 0, 8예제 모두 LO_맞음 > 0(P 4/4, Q 4/4). 1회 실행이며 중단·재실행은 없었다.

### 첫 구별 음 log-odds (teacher forcing)
| 평가 prefix | 후보 P / Q | step 0: L(base = 모든 조건) | step 32: L(Cmaj7) | L(Cm7) | L(0 벡터) | Δ | P 예제 LO_맞음 | Q 예제 LO_맞음 |
|---|---|---|---|---|---|---|---|---|
| E8 | E4 / Eb4 | -0.322 | 0.789 | -1.540 | -0.322 | 2.329 | 0.789 | 1.540 |
| E9 | B4 / Bb4 | 0.249 | 1.564 | -1.936 | 0.249 | 3.501 | 1.564 | 1.936 |
| E10 | E5 / Eb5 | 1.307 | 1.056 | -0.375 | 1.307 | 1.431 | 1.056 | 0.375 |
| E11 | B4 / Bb4 | -0.168 | 1.008 | -2.377 | -0.168 | 3.384 | 1.008 | 2.377 |

- step 0에서는 adapter가 0이라 모든 조건의 L이 base와 같다(차이 0.0). base는 4개 중 2개(E9, E10)에서 이미 P음을 선호하고, 2개(E8, E11)에서는 Q음을 선호했다
- step 32: Cmaj7 조건이면 4개 모두 L > 0(P음 선호), Cm7 조건이면 4개 모두 L < 0(Q음 선호)이다. 같은 prefix에서 조건을 바꾸면 방향이 뒤집혔다
- E10은 base가 이미 P음을 선호했고(1.307), Cmaj7 조건에서 오히려 조금 내려갔다(1.056). 그래도 0보다 크다. 이 adapter의 효과는 절대값을 올리는 것이 아니라 두 조건 사이의 차이(Δ 1.43–3.50)로 나타났다
- 0 벡터 조건은 bias가 없어 구조상 base와 같다. 수치로도 차이 0.0이었다
- 훈련 family 8개에서도 Δ > 0이 8/8이었다(정보 항목)

| E9 | -6.41 / -6.66 | -4.08 / -5.64 | -5.77 / -3.84 |

- 두 후보의 log p는 −2.8 ~ −6.9다. 확률로는 약 0.1–6%다. 조건은 **두 후보 사이의 상대 선호**를 바꿨다. 하지만 이 위치에서 모델이 3도나 7도를 고를 확률 자체는 여전히 낮다

## 해석 범위
- 말할 수 있는 것: **같은 prefix에서 외부 코드 조건(Cmaj7/Cm7)을 구별해 첫 구별 음의 상대 선호를 바꾸도록, 작은 모듈을 32 step으로 학습할 수 있었다**(평가 prefix 4개, C 근음)
- 말할 수 없는 것
  - 생성 제어(위 생성 결과는 반대 방향의 증거다)
  - 코드 전환 시점의 반응(경계 첫 음 지연 한계는 그대로다)
  - 다른 조나 코드 종류, 실제 음악, 스타일
- 쌍 음악 자료 부족은 그대로다. 실제 악보·티그랑 학습은 보류다
- adapter는 저장소 밖 `synthetic_diagnostic_only` 산출물이다. 다시 쓰거나 배포하지 않는다

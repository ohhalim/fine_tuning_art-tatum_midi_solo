# 기본 모드 토큰 예산 — 사전 등록

**이 절은 실행 전에 작성했다.**

## 문제 (#1503)
기본 모드(코드 primer 없음)는 `--generation-tokens 96`이 마디 전체 예산이다. 음이 촘촘하면 마디를 채우기 전에 토큰이 떨어져 블록이 무효(fallback)가 된다. fallback 비율은 base 18.8%, Tatum 37.5%, 멜다우 12.5%였다(#1499 쌍). 이제는 KV 캐시와 병합으로 토큰당 비용이 줄었다.

## 변경 후보 (코드 변경 없음)
기존 CLI 옵션만 바꾼다: `--generation-tokens 192 --max-sequence 256`. 코드 primer 모드의 마디당 예산(2 × 96)과 같다.

## 조건
- 모델: Tatum 완성, 멜다우 #1497
- 기본 모드(코드 primer 없음), 128 BPM, 16마디, seed 42/43/44, 현재 런타임 기본값(늦은 fetch, 시작 예산 0.5마디)
- 기준 arm(96/192)과 후보 arm(192/256)을 같은 세션에서 잰다. 모델당 arm당 3회, 총 12회

## 판정
- 두 모델 모두 후보 arm의 fallback이 기준 arm보다 적고 실행당 1마디 이하이며, 미스 0이고, 생성 최대 시간이 시작 예산(0.5마디 = 937 ms) 안이면 → 기본 모드 권장 옵션으로 문서화한다(기본값은 바꾸지 않는다)
- 아니면 기본 모드를 "비권장, 코드 primer 모드 사용"으로 문서화한다

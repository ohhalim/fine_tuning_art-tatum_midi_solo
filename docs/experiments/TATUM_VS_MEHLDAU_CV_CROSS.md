## 왜
#1499의 3×3에서 개인화 정도의 우열이 가중 방식에 따라 뒤집혔다. 멜다우 holdout이 2곡뿐이었기 때문이다. 이미 학습한 CV fold 어댑터로 곡 표본을 **연주자당 16곡**으로 늘려 다시 판정한다.

## 재료 (모두 #1499 산출물, 수정 없음)
- 공통 base: `outputs/tvm/common_base/checkpoint_epoch8.pt`
- 어댑터: 연주자당 4개, `outputs/tvm/cv_{tatum,mehldau}_fold{k}/lora_update128.pt`. 128은 두 연주자 모두의 CV 선택값이다
- 곡 세트
  - Tatum train16과 멜다우 train16. 각 곡은 정확히 한 fold에서 held-out이다
  - 일반 재즈 probe 100곡(`tatum_generic_probe_list.json`)

## 측정 (곡 단위, 곡마다 겹치지 않는 512 crop 전부, 일반 재즈는 가운데 1024토큰, LS 없음)
연주자 a의 어댑터마다 세 가지를 잰다.
- **자기 Δ:** a의 곡 16개 각각을, 그 곡을 held-out으로 둔 fold 어댑터로 잰 ΔCE(base 대비) → 16개 값. 모두 그 어댑터가 보지 않은 곡이다
- **상대 Δ:** 상대 연주자 곡 16개 각각을, a의 fold 어댑터 4개로 잰 ΔCE의 평균 → 16개 값. a의 어떤 어댑터도 보지 않은 곡이다
- **일반 Δ:** 일반 재즈 100곡 각각을, a의 fold 어댑터 4개로 잰 ΔCE의 평균 → 100개 값

지수(곡 macro, token 가중도 함께 보고)
- 자기 개선 = mean(자기 Δ). **< 0 필수**
- 특화도 = mean(자기 Δ) − mean(일반 Δ)
- 특이성 = mean(자기 Δ) − mean(상대 Δ)

## 우열 판정 (사전 고정)
- **D_spec = 특화도_Tatum − 특화도_멜다우**, **D_specif = 특이성_Tatum − 특이성_멜다우**. 음수면 Tatum 쪽이 더 개인화된 것이다
- 95% CI는 bootstrap 2,000회로 구한다. 각 연주자의 자기 곡 16개와 상대 곡 16개는 독립으로 재표집한다. 일반 재즈 100곡은 두 어댑터에 같은 곡 인덱스로 짝지어 재표집한다
- **CI가 0을 포함하지 않으면 그 방향으로 우열을 선언한다. 0을 포함하면 "차이 없음 / 미확정"으로 기록한다**
- 특화도와 특이성이 서로 다른 결론을 내면 둘 다 그대로 보고한다

## 한계 (사전 기재)
- 예산 128은 같은 CV held-out 결과로 골랐다. 선택 편향이 약하게 있을 수 있다(두 연주자에 대칭)
- Tatum 학습셋 토큰은 2.5배다(#1499와 같은 비대칭)
- 곡 난이도가 달라 raw CE는 비교하지 않는다

## 사전 등록 정정 — 아스트라 리뷰 반영 (결과 계산 전, 2026-09-29)
위 "우열 판정" 절을 아래로 **대체**한다.
1. **짝지은 재표집:** Tatum 16곡은 Tatum 어댑터의 "자기" 세트이자 멜다우 어댑터의 "상대" 세트다(멜다우 곡도 마찬가지). 연주자마다 곡 인덱스를 한 번 뽑아 그 곡을 쓰는 모든 역할에 같이 적용한다. 일반 100곡도 짝지어 재표집한다. 역할별 독립 재표집은 공분산을 버리므로 쓰지 않는다
2. **선택 후 탐색 분석이다.** u128은 바로 이 CV held-out 점수로 선택됐다. 새 독립 검증이 아니다. 대칭이라는 이유로 편향이 약하다고 단정할 수 없다. CI는 **고정된 fold 모델과 선택된 예산에 조건부인 곡 재표집 구간**이다. **확증적 우열 선언은 하지 않는다.** CI가 0을 제외하면 "데이터와 일관된 방향(탐색)"으로만 적는다. 확증에는 독립 holdout이나 nested CV가 필요하다(후속 경계. 이번 범위는 새 학습 없음)
3. **16개 값은 완전히 독립이 아니다.** 같은 fold 모델을 공유하고, fold 사이에 학습곡이 겹친다. 곡 bootstrap은 재학습 변동을 포함하지 않는다. fold별 결과를 함께 적는다
4. **CI에 0이 들어가면 "차이를 확인하지 못함"이다**("차이 없음"이 아니다). #1499에서 순위가 뒤집힌 원인도 val2 하나로 단정하지 않는다. 가중 방식(token/macro)과 곡 길이별 개선 차이를 후보로 함께 기록한다(곡 길이와 자기 개선의 순위 상관을 탐색값으로 보고)
5. **12곡으로 학습한 fold 모델의 결과를, 16곡으로 학습한 최종 export 두 모델의 직접 우열로 일반화하지 않는다**

## 결과 — 선택 후 탐색 분석 (확증 아님)
원시값: `docs/experiments/tvm/cv_cross.json`. CI는 고정된 fold 모델(u128)에 조건부인 짝지은 곡 재표집 구간이다(2,000회). 재학습 변동은 포함하지 않는다.

**지수 (곡 macro, 괄호는 token 가중)**

| 어댑터 | 자기 곡 16 | 상대 연주자 곡 16 | 일반 재즈 100 | 특화도 [CI] | 특이성 [CI] |
|---|---|---|---|---|---|
| Tatum | **−0.063** (−0.063) | −0.005 | −0.021 | −0.042 [−0.049, −0.034] | −0.057 [−0.068, −0.047] |
| 멜다우 | **−0.047** (−0.040) | −0.011 | −0.015 | −0.033 [−0.046, −0.021] | −0.036 [−0.049, −0.025] |

**우열 (Tatum − 멜다우)**
- D_spec = −0.009, CI [−0.022, +0.005] → **차이를 확인하지 못함**
- D_specif = −0.021, CI [−0.037, +0.0002] → **차이를 확인하지 못함**(상한이 0에 닿는다)
- 방향은 두 지수 모두 Tatum 쪽이지만 확증된 우열이 아니다. 확증에는 독립 holdout이나 nested CV가 필요하다

**fold별 (각 fold 모델, 자기 held-out 4곡)**

| fold | Tatum 자기 / 특화도 / 특이성 | 멜다우 자기 / 특화도 / 특이성 |
|---|---|---|
| 0 | −0.051 / −0.032 / −0.050 | −0.042 / −0.028 / −0.028 |
| 1 | −0.066 / −0.043 / −0.057 | −0.060 / −0.043 / −0.049 |
| 2 | −0.063 / −0.042 / −0.059 | −0.051 / −0.035 / −0.039 |
| 3 | −0.071 / −0.049 / −0.063 | −0.036 / −0.024 / −0.029 |

fold 간 범위가 겹친다(멜다우 fold 1의 특화도 −0.043은 Tatum fold 0의 −0.032보다 크다).

**해석**
1. **두 어댑터 모두 자기 연주자에게 특이적이다.** 16곡 기준으로 상대 연주자 곡 개선이 일반 재즈 개선보다 작다(Tatum 어댑터: 멜다우 곡 −0.005 vs 일반 −0.021, 멜다우 어댑터: Tatum 곡 −0.011 vs 일반 −0.015)
2. **#1499 해석 정정:** #1499는 "Tatum 어댑터의 이득 일부가 멜다우 곡으로 옮겨간다"고 적었다(멜다우 val2에서 −0.028). 16곡으로 보면 이 현상이 재현되지 않는다(−0.005). **val2 2곡에서의 관측이었다**
3. **token/macro 순위 뒤집힘의 원인 후보:** 멜다우는 곡 길이와 자기 개선의 순위 상관이 **+0.45**다(짧은 곡일수록 더 개선). 그래서 macro(−0.047)가 token(−0.040)보다 크다. Tatum은 상관이 **+0.01**이다. #1499에서 순위가 뒤집힌 데는 val2의 작은 표본과 함께 이 곡 길이 효과도 후보다(인과 검증 없음)
4. 이 결과는 12곡으로 학습한 fold 모델의 것이다. 16곡으로 학습한 최종 export 두 모델의 직접 우열로 일반화하지 않는다

## 결론
- 연주자당 16곡으로 늘려도 **Tatum과 멜다우의 개인화 정도 차이는 확인되지 않았다**(탐색 분석, 방향은 Tatum 쪽)
- 두 어댑터가 모두 연주자 특이적이라는 점은 16곡에서도 유지된다
- #1499의 "Tatum 이득의 멜다우 전이"는 val2에서만 나타난 관측으로 정정한다
- 확증을 위한 다음 경계: nested CV(예산 선택과 평가를 분리)나 새 독립 holdout. 멜다우는 추가 자료가 없어 nested CV만 가능하다

# 실제 cache 상태로 연속 요청 재생: 동등성과 블록 전체 시간 (사전 등록)

## 1. 왜

- #1793: 앞부분 재사용으로 다시 계산할 양은 크게 줄었고(S 중앙값 116토큰), 10개 사례에서 결과가 전체 재계산과 같았습니다
- 그러나 그 비교는 앞 요청 입력 **전체**를 KV에 넣은 상태였습니다. 실제 생성 루프(`rt_producer.py`의 `TokenStream`)는 마지막으로 샘플한 토큰이 아직 KV에 들어가지 않았을 수 있고, 새 문맥 끝 위치의 logits가 없을 수 있습니다
- 블록 전체 시간(재계산 + 블록 토큰 n개 생성의 n − 1회 decode)은 대표 지점에서 decode까지 포함해 실제로 잰 적이 없습니다(#1794 M1)

## 2. 질문 (하나)

실제 cache 상태(KV 유효 끝이 정해진 상태)에서 재사용 규칙대로 계산하면 전체 재계산과 같은가, 그리고 그때 블록 전체 시간은 얼마인가?

## 3. 재사용 규칙 (실행 전 고정)

- 앞 요청이 끝난 상태: KV에는 앞 요청 b 입력 Pseq 중 **유효 끝 V**까지만 들어 있습니다
  - `fed`: V = len(Pseq) (마지막 토큰까지 들어감)
  - `unfed`: V = len(Pseq) − 1 (마지막 샘플 토큰이 아직 안 들어감, 실제 루프의 기본 상태)
- 새 요청 문맥 N에 대해 P_reuse = min(공통 앞부분(Pseq, N), V). crop 상태(keep_from·base_ms)가 바뀌었으면 P_reuse = 0
- P_reuse = len(N)이면(S = 0) 새 문맥 끝 logits가 없으므로 P_reuse = len(N) − 1로 마지막 1토큰을 다시 계산합니다(옛 더 긴 문맥의 logits 재사용 금지)
- N[P_reuse:]를 위치 P_reuse부터 계산하고, 그 뒤 옛 KV는 `max_kv_pos = len(N) − 1`로 가립니다

## 4. 사례 (실행 전 고정, #1793 count.json에서)

- 긴 P 4개: crop이 아닌 쌍 중 P가 1,692 / 2,142 / 2,877 / 3,343에 가장 가까운 쌍(동률이면 S가 #1793 대표 S에 가까운 쪽, 그다음 곡·k 순)

- 각 사례를 `fed`·`unfed` 두 상태로 재생합니다(12회)

## 5. 비교와 음성 대조 (실행 전 고정)

- 통과: 다시 계산한 모든 위치의 top-1이 전체 재계산과 같고, 마지막 위치 logits 최대 |차| ≤ 1e-3
- 음성 대조(실패로 잡혀야 함)
  - `stale_beyond_valid`: unfed 상태에서 V를 무시하고 P = 공통 앞부분으로 재사용(유효 범위 밖 재사용)
  - `skip_change`: 공통 앞부분이 len(N)보다 짧은 긴 P 사례에서, 갈린 위치 뒤 8토큰을 다시 계산하지 않고 옛 KV를 쓴 채 그 뒤부터 계산(만료·held 갱신 누락)
  - 음성 대조가 하나라도 "통과"로 나오면 비교가 둔감하다고 보고 6절 시간 결론을 내지 않습니다
- 양성 사례가 하나라도 실패하면 6절 시간 결론을 내지 않습니다

## 6. 블록 전체 시간 (동등성·음성 대조 통과 뒤)

## 9. 읽기

- **실제 cache 상태(마지막 토큰 미입력 포함)에서도 재사용 규칙은 전체 재계산과 같은 결과를 냈고, 잘못된 재사용은 잡혔습니다.** 지금 계약 그대로 앞부분 재사용으로 입력 경로를 만들 수 있다는 구현 근거입니다
- 시간: 보통 밀도의 블록(15토큰)은 긴 문맥에서도 1박 안이었습니다. 빽빽한 블록(30토큰)은 긴 문맥에서 넘칩니다. 이 경우를 어떻게 다룰지(블록 토큰 상한, 추측 생성분 재사용, 마감 완화 등)는 비용 숫자만으로 정하지 않는 제품 결정입니다(아스트라 #1792·#1794 판단)
- 다음 후보(아스트라 권고 순서): opt-in 가상 MIDI 입력 → producer 연속 경로 검토. 실물 키보드·기본 경로 변경·자동 fallback 채택은 임계값 통과 전에 하지 않고, crop 블록과 마감 초과 블록의 처리(안전 중단, 기존 확정음 유지 등)를 먼저 명시합니다
- 말하지 않는 것: 왼손 문맥이 생성에 도움이 된다, 실시간에서 늘 마감을 지킨다, 솔로 품질·개인화 성공

## 10. 리뷰 반영 (아스트라 msg_8805130fea29, LOW만, 새 실행 없음)

- **시간의 범위:** 8.3의 "블록 전체 시간"은 suffix forward + n − 1회 teacher-forced forward만입니다. KV 상태(P, V) 재구성은 타이머 밖이고 쌍마다 다시 만들었습니다. MIDI 수신, snapshot, 병합·토큰화·공통 앞부분 계산, 샘플링·마스크, 예약·송출 비용은 빠졌습니다. 실제 연속 운용이나 끝-끝 지연이 아닙니다. 특히 longP_2142의 462.8 ms는 남은 여유가 5.95 ms뿐이라 운영 가능 판정이 아닙니다

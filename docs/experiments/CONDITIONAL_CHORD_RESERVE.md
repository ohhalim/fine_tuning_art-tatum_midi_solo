# 코드 guide 음이 실제로 잘릴 때만 예약 — 공동 검증 (사전 등록)

작성 2026-09-29. 이슈 #1567. `style_verified: false` · `musical_quality_verified: false` · 가상 CoreMIDI 포트

**이 절은 측정 전에 작성했다.** 구현은 측정 전에 끝냈다.

## 배경
- #1553의 "항상 예약"은 촘촘한 입력에서 코드톤을 올렸지만, 음역 따라가기를 5/6에서 2/6로 떨어뜨렸다. 그래서 기본값을 off로 되돌렸다(#1558)
- Astra 리뷰
  - '>48토큰'은 코드가 실제로 잘렸다는 뜻이 아니다
  - 안 잘리면 토큰 동일, 잘리면 코드 보존, 음역 따라가기, 지연·fallback을 함께 검증하기 전에는 기본 on을 재승인할 수 없다

## 변경 (실험 옵션, 기본 off)
- `--reserve-chord-when-cut`: 입력이 있을 때 표준 primer(코드 음과 입력 음을 시간순으로 합쳐 48토큰으로 자름)를 먼저 만든다
  - 코드 guide 음의 음높이가 하나라도 빠졌으면 #1553 방식(최신 입력 + 코드 진술 전체)으로 바꾼다
  - 빠지지 않았으면 표준 primer를 그대로 쓴다(토큰이 기존과 같다)
- 리포트: `reserve_chord_mode`, `chord_reserved_blocks`
- 알려진 한계: 입력 음이 guide 음과 같은 음높이면, 잘린 guide 음을 남은 것으로 셀 수 있다

## 측정 (Tatum 완성, 반 마디 블록, 128 BPM, 16마디, seed 42/43/44, 모두 `--reserve-chord-when-cut`)
- S: 드문 입력 5음(#1542 조건) — 높은 음역, 낮은 음역
- D: 촘촘한 입력 16음, C4–C5 음계(#1550 조건)
- H: 촘촘한 높은 음역 16음, C6–C7 음계(84 86 88 89 91 93 95 96 95 93 91 89 88 86 84 86). 같은 조건의 **off arm**도 잰다

## 판정 (모두 충족하면 공동 검증 통과. 기본값 변경은 통과해도 Astra·사용자 판단 전까지 하지 않는다)
1. 토큰 동일: S 6회의 연주 마디가 #1542 원 실행과 전부 같다. 따라서 음역 따라가기는 #1542의 5/6과 같다
2. 코드 보존: D와 H에서 예약 블록(`chord_reserved_blocks`)이 1개 이상이다. D의 입력 블록 코드톤 비율이 #1550(off)보다 높은 seed가 2/3 이상이다
3. 음역 따라가기(촘촘한 입력): H의 when-cut arm에서 입력 블록 평균 음높이가 무입력보다 높은 seed가 2/3 이상이다. off arm 값도 함께 보고한다
4. fallback: 모든 실행 0(미스는 보고만 한다. 측정 시각의 머신 부하도 적는다)

# 실시간 코드 입력 — 짚은 코드를 다음 블록 코드 진술로 (사전 등록)

작성 2026-10-01. 이슈 #1576. 가상 CoreMIDI 포트. `style_verified: false` · `musical_quality_verified: false` · 실물 키보드·FL Studio 미측정

**판정 기준은 측정 전에 고정했다.** 실행 뒤에는 결과 절만 덧붙인다.

## 문제
- 코드 진행이 실행할 때 `--chords`로 고정된다(`docs/FUTURE_IDEAS.md` §1). 곡마다 진행이 바뀌는 라이브 세트에서는 쓸 수 없다

## 변경 (opt-in, 기본값 불변)
- `--live-chords off|observe|follow`(기본 off), `--chord-split N`(기본 60). `--input-port`와 `--half-bar-blocks`가 필요하다
- 인식(`inference/control/live_chords.py`)
  - 블록 생성 때 받은 입력 스냅샷의 끝에 **눌려 있는** split 아래 음의 pitch class로 판단한다
  - 템플릿: maj7, 7, m7, m7b5, dim. 눌린 음이 모두 코드음이고, 근음과 3음이 있고, 서로 다른 음이 3개 이상이어야 한다
  - 3화음은 코드 가이드 어휘로 이름 붙인다(C-E-G → Cmaj7, A-C-E → Am7, B-D-F → Bm7b5)
  - 동률이면 코드음이 더 많은 것, 근음이 베이스인 것, 템플릿 순서로 고른다
- follow: 인식한 코드를 그 블록의 코드 진술로 쓴다. 손을 떼면 마지막 코드를 유지하고, 첫 인식 전에는 `--chords`를 쓴다
- observe: 인식만 기록하고 코드 진술은 `--chords` 그대로다(대조군)
- 두 모드 모두 입력 음 자체는 지금처럼 primer에 들어간다. 그래서 두 모드의 차이는 **코드 진술만**이다
- 리포트 `live_chords`: 블록별 코드·출처(static/live/held), 코드 변화 시각, 변화 → 반영 블록 지연
- 한계: fallback 블록은 실행 때 만든 정적 진행을 쓴다. 근음 없는 보이싱(rootless), 텐션 포함 코드는 인식하지 않는다

## 측정 (`scripts/run_live_chord_probe.py`)
- Tatum 프리셋(반 마디 블록), 16마디(30초), 128 BPM, 정적 진행 `--chords Cmaj7`
- probe가 가상 포트로 코드를 보낸다. 근음 위치 4음(근음 36–47), 3.75초(4블록)씩 누르고 다음 코드 직전에 뗀다
  - 순서: Dbmaj7, Gb7, Bm7, Bbm7b5, E7, Abmaj7(정적 Cmaj7과 겹치는 음이 적은 코드, 22.5초)
  - 첫 채택 블록이 출력된 뒤 1초에 시작한다
- 실행: seed 42, 43, 44 × {observe, follow} = 6회. 같은 seed끼리 짝을 짓는다
- 대상 코드: 블록 시작 시각에 눌려 있던 코드(리포트의 변화 시각 기준). 첫 변화 전 블록은 뺀다
- 코드톤 비율: 채택된 블록의 연주 음 중 대상 코드음 비율(음 수 합 기준)

### 기대 효과 보정 (등록 전, 기존 실행 데이터)
- 쇼케이스·#1572 문맥 실행에서 연주 음의 코드톤 비율
  - 실제 코드 기준: Tatum 0.495, 멜다우 0.534
  - 위 순서의 다른 코드 기준: Tatum 0.304, 멜다우 0.289
- 완벽히 따라가면 상한은 약 +0.19다. 반영 지연이 1블록이면 4블록 중 1블록은 이전 코드라서 기대 차이는 약 +0.14다
- observe도 입력 음을 primer로 보므로 일부 따라갈 수 있다. 그래서 기준은 기대치의 약 절반인 +0.08로 둔다

## 판정 (모두 충족하면 기능을 opt-in으로 합친다. 프리셋 기본값은 바꾸지 않는다)
1. 인식: 6회 모두 변화 기록이 보낸 6개 코드와 순서·구성음까지 같다
2. 추종: 코드톤 비율 follow − observe가 3쌍 평균 ≥ +0.08이고, 3쌍 모두 양수
3. 지연: follow 3회의 모든 변화에서 코드 도착 → 반영 블록 시작 ≤ 1,875 ms(2블록). 중앙값을 보고한다
4. 실시간: 6회 모두 fallback 0(미스는 보고만 한다)
- 실패하면 원인을 기록하고 이번 단위에서 기준·코드 순서·유지 시간을 다시 탐색하지 않는다
- 통과해도 실물 키보드·FL Studio 경로, 음악 품질, 코드 진행 "연주감"은 검증하지 않은 것으로 남긴다

## 정정 (측정 전, 데이터 없음)
- 처음 등록은 24마디, 코드 8개였다. 런타임이 이 경로를 8–16마디로 제한해서 6회 모두 시작 단계에서 종료했다(측정값 없음)
- 16마디(30초)에 맞춰 코드를 6개로 줄였다(Ebm7, Gbmaj7 제외). 기준값과 비교 방식은 그대로다

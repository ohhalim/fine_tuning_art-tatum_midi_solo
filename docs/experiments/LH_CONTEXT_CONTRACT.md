## 계약 — `scripts/lh_context.py` (순수 Python)

| 항목 | 정의 |
|---|---|
| 관측 창 | 요청 k ≥ 1에서 onset이 [max(s_k − W, base_ms), s_k)인 사람 음. **W = 7,500 ms**(8블록, 128 BPM 4마디). base_ms는 세션이 crop으로 지운 시간의 끝이라, 남은 오른손 문맥보다 이른 왼손은 넣지 않습니다. 시각은 반올림해 정수 ms로 씁니다. k = 0(cold)은 왼손을 넣지 않습니다(a = b = c) |
| held 음 | s_k에 아직 울리는 음(off > s_k)은 원시 시각에서 **off = min(관측 off, s_k)로 자른 뒤** Aria 형식으로 인코딩합니다(P1). 이 끝은 s_k에 실제로 뗐다는 정보가 아니라 **표현 제약 때문에 둔 가상 종료**입니다. 모델은 held와 released를 구분하지 못하므로, held 층에서 효과가 없더라도 왼손 정보 전체를 기각하는 근거로 쓰지 않습니다. 같은 시각 처리 순서: onset = s_k인 음은 넣지 않고, off = s_k인 음은 released, off > s_k만 held입니다. 오른손 이력은 이미 확정된 teacher-forced 이력이라 s_k 뒤 onset·끝이 있어도 자르지 않습니다 |
| 층 | 요청을 셋으로 나눠 보고합니다. empty(창 안 왼손 0개), held(창 안에 s_k에서 울리는 음 있음), released(나머지) |
| 왼손 토큰 | Aria abs 규칙을 그대로 따릅니다(`ariautils` 설정: time_step 10 ms, abs_time_step 5,000 ms, max_dur 5,000 ms, velocity 단계 10, 토크나이저의 이진 탐색 그대로). onset은 구간 안 가장 가까운 10 ms, dur는 가장 가까운 10 ms(0이면 10), 5,000 ms 상한. velocity는 **원본에서 복구한 값**을 같은 규칙으로 양자화합니다. 공식 토크나이저와 맞추려고 시각을 정수 ms로 반올림한 뒤 인코딩합니다(1 tick = 1 ms MIDI와 같은 입력) |
| 병합 | 오른손 문맥 토큰은 하나도 바꾸지 않습니다. 왼손 note(piano, onset, dur)를 같은 5초 구간 안에서 onset 순서 자리에 끼워 넣습니다. 같은 onset이면 왼손을 먼저 둡니다(Aria 토크나이저는 시작 tick으로만 정렬하므로 동률 순서는 정의되지 않음. 고정 규칙으로 둠) |
| 넣는 위치 | 문맥(ctx_end 앞)에만 넣습니다. continuation(window + boundary)에는 넣지 않습니다. 왼손 onset < s_k < h_(k−1) ≤ 첫 continuation onset이므로 시간 순서가 맞습니다 |
| 구간 경계 | 왼손 onset이 속한 5초 구간의 `<T>`는 오른손 문맥에 이미 있습니다(그 경계 시각 ≤ s_k < h_(k−1)이면 확정됨). 없는 경우는 계약 위반으로 멈춥니다 |
| c 기증자 | **다른 dev 곡만**(같은 곡 다른 위치는 별도 질문이라 쓰지 않음). 요청 k′ ≥ 1에서 같은 길이 L = s_k − 창 시작의 창 [s_k′ − L, s_k′)을 봅니다. 그중 창 안 왼손 음 수가 같고, held 여부가 같고, 자른 뒤 총 울림 길이가 가장 가까운 것. 동률은 (\|k′ − k\|, 곡 번호, k′) 순으로 완전히 정합니다. 후보 선택에는 두 창에서 그 시점에 관측 가능한 왼손만 쓰고, 오른손 target·NLL·미래 실제 off는 쓰지 않습니다. 기증자 음은 s_k − s_k′만큼 시간을 옮기고 전조하지 않습니다. 기증자 음의 자르기는 기증자 자신의 s_k′ 기준입니다. 맞는 기증자가 없으면 그 요청은 c에서 빼고 수를 보고합니다. empty 층은 기증자가 필요 없습니다(c = a) |
| crop | a의 세션 상태(#1758 `session_requests`, 오른손만으로 결정)를 기준으로 합니다. b나 c의 병합 문맥이 안전 한계(`needs_crop`)를 넘으면, 세 문맥 모두에 같은 더 늦은 `<T>`에서 추가로 자르고 기록합니다. 세 문맥의 base_ms와 첫 유지 토큰은 늘 같습니다 |
| 점수 위치 | 오른손 window(그리고 boundary는 별도 층) label만. 문맥 길이가 달라 label의 절대 배열 위치는 arm마다 다릅니다. arm별 label 시작 위치를 따로 계산하고, label 토큰 목록이 같은지 검사합니다. 이번에는 점수를 계산하지 않습니다 |
| 출처 태그 | 병합 결과의 모든 토큰에 `hdr`·`rh`·`lh` 태그를 붙입니다 |
| KV | 과거 위치에 왼손을 끼우거나 held 길이를 바꾸면 기존 KV가 무효가 됩니다. 이번에는 매 요청 전체 prefill을 전제로 하고, 기존 저지연 KV 결과를 재사용한다고 주장하지 않습니다 |
| 부적격 표기 | c의 실제 사용 음 수·held 여부가 b와 다르면 부적격으로 표기합니다. 결과를 본 뒤 기증자를 다시 찾지 않습니다 |

# 패턴 캐시 디코딩 — 앞 패턴을 잇는 음의 확률을 올리면 재등장이 실제 수준에 가까워지는가 (사전 등록)

작성 2026-10-02. 이슈 #1604. 판정 규칙은 실행 전에 고정했다. 독립 리뷰는 사용자 지시로 나중에 일괄로 받는다. `musical_quality_verified: false`.

## 배경
- 자유 생성의 음정 재등장(IR)이 실제보다 크게 낮다
  - 자연 문맥: 0.007(#1597)
  - temperature 0.6: 0.017(#1600)
  - 반복 음 가중 학습: 변화 없음(#1602)
  - 실제 연주: 0.052
- 학습과 입력과 온도로는 격차가 남았다. 이번에는 **생성 단계**에서 직접 다룬다

## 방법 (`scripts/pattern_cache.py`)
- 샘플링하는 매 단계에서, 지금까지 시퀀스의 윗선율 마지막 3음이 만든 음정 두 개를 본다
- 그 두 음정이 앞 8초 안의 음정 3-gram 앞부분과 같으면(겹치지 않는 창), 그 3-gram을 완성하는 음높이의 note_on 로짓에 **b = ln 3**을 더한다. 확률이 약 3배가 된다
- 확률만 바꾼다. 음을 넣는 것은 여전히 모델의 샘플링이다. 리듬은 바꾸지 않는다
- 모델 코드: `MusicTransformer.generate(logits_processor=...)`를 추가했다. 문법 마스크 뒤에 적용하고, 기본값 None이면 기존과 같다

## 질문 (하나)
같은 위치·같은 자연 문맥(256토큰)·T 1.0에서, b = ln 3 패턴 캐시를 켜면 끈 것보다 IR이 실제 연주 수준에 가까워지는가. 기계적 반복이나 복사가 생기면 안 된다.

## 고정 설계
- 위치·target·primer: #1600과 같다(`pick_positions`, N primer, seed 2개). 두 갈래가 같은 seed를 쓴다
- 모델: Tatum 완성, 공통 base. 멜다우 holdout 2곡은 기술 통계만 낸다
- 데이터: 진단용 val12(파이프라인 확인), 평가용 fresh12(판정. 재사용 셋)
- 디코딩: T 1.0, top-k 32, top-p 0.95, grammar mask, 2초. b = ln 3 하나만 쓴다(탐색 없음)
- 지표: IR(주지표), VR, XR, 반복률, 복사 비율(앞 8초와 같은 연속 5음), 유효율, 캐시가 작동한 단계 비율

## 판정 (평가용, 모델별, 실행 전 고정)
- **통과:** 모두 충족
  1. IR(켬) ≥ 0.5 × 실제 IR
  2. IR(켬) − IR(끔)의 곡 bootstrap 95% CI 하한 > 0
  3. 보호 조건(켬)
     - 반복률 ≤ 실제 반복률 + 0.15
     - 복사 비율 ≤ max(0.25, 실제 × 2)
     - 유효율 ≥ 0.9
- 미달이면 기록하고, b나 규칙을 이 단위에서 다시 탐색하지 않는다
- 통과해도 런타임 기본값은 바꾸지 않는다. 런타임 opt-in과 청취 확인은 별도 이슈로 한다

# Aria 반복 루프 진단 (기존 출력, 새 생성 없음)

작성 2026-10-06. 아스트라 #197 합의. 입력·정의·해시는 `loop_diag/manifest.json`, 표 원자료는 `loop_diag/loops.json`, 스크립트는 `scripts/aria_loop_diag.py`다. `musical_quality_verified: false`.

## 계기
- 사용자 T3c 판정: "기존 연주가 끝나면 계속 한 패턴이 반복되는 무한루프에 들어가는 것이 많다"
- T3에서도 사용자가 "저음으로 내려가거나 계속 반복하는 버그"를 짚었다

## 방법
- 대상: T3(P1·P2·P3 × 2)와 T3c(TA·TB × 2) 출력 10개. 새로 생성하지 않았다
- 생성 부분: 출력 음에서 프라이머 토큰 음을 (pitch, onset) 다중집합으로 지운 나머지
- 이벤트: 30 ms 안에 시작한 음들을 하나의 화음 이벤트로 묶는다
- 루프: 이벤트 i와 i+k가 정확히 같은 구간이 주기 k ≤ 24 이벤트로 3회 이상, 4초 이상 이어지는 것. 가장 긴 것 하나를 고른다
  - 정확 일치만 센다. 조금씩 변하는 반복이나 의도된 오스티나토는 이 정의로 구별하지 못한다
- 종료 원인: 토큰 로그는 남기지 않았다. 10개 모두 생성 음이 338–340개로 1024토큰 예산(음당 약 3토큰)과 맞으므로, EOS가 아니라 길이 상한에서 끝난 것으로 추정한다

- **루프가 있는 출력 4/10.** 4개 모두 생성이 끝날 때까지 빠져나오지 못했다
- **유형 둘**
  - 저음 붕괴(P2-2, TB-1): 맨 아래 옥타브 화음 하나(A0+A1, D1+D2+D3)를 0.1–0.2초 간격으로 반복. 평균 음높이가 54→27, 61→38로 떨어진다. 반복 단위는 프라이머에 없던 이벤트다
  - 패턴 반복(TA-2, P3-1): 0.2초(C#4+C#5 / C#3 교대)나 1.5초(11이벤트 두 손 패턴) 단위. 음역은 거의 그대로다. TA-2의 단위 이벤트는 프라이머에도 있다
- 루프 진입 시점은 생성 후 2–22초로 제각각이다
- 프라이머 4개(P1–P3, TA, TB)에는 이 정의의 루프(정확 반복 4초 이상)가 없었다

## 해석 한계
- 10개 샘플의 관측이다. 생성 길이가 서로 달라서 같은 시간 노출 기준의 발생률로 쓰지 않는다
- 오스티나토와 결함을 저음이나 음 종류만으로 같다고 보지 않는다. 다만 사용자가 루프를 결함으로 들었다
- 원인(샘플링 퇴화, 모델 분포, 프라이머 성격)은 확정하지 않았다

## 다음 가설 하나
**한번 반복이 시작되면 모델 스스로의 출력이 그 반복의 확률을 높여 빠져나오지 못한다(자기 강화).**
- 근거: 루프 4개가 모두 끝까지 이어졌다. 저음 붕괴 2개는 프라이머에 없던 단위다. 프라이머에는 정확 반복 루프가 없었다
- 새 생성 없이 시험하는 방법: 이미 있는 루프 구간을 모델에 teacher-forcing으로 넣고, 반복 횟수가 늘수록 "다음도 같은 이벤트"의 확률이 올라가는지 본다
- 이 가설이 맞아도 해법(반복 패널티, 짧은 블록, 외부 입력으로 끊기)을 바로 성공으로 등록하지 않는다

# Aria 반복 루프 진단 (기존 출력, 새 생성 없음)

작성 2026-10-06. 아스트라 #197 합의. 입력·정의·해시는 `loop_diag/manifest.json`, 표 원자료는 `loop_diag/loops.json`, 스크립트는 `scripts/aria_loop_diag.py`다. `musical_quality_verified: false`.

## 계기
- 사용자 T3c 판정: "기존 연주가 끝나면 계속 한 패턴이 반복되는 무한루프에 들어가는 것이 많다"
- T3에서도 사용자가 "저음으로 내려가거나 계속 반복하는 버그"를 짚었다

## 방법
- 대상: T3(P1·P2·P3 × 2)와 T3c(TA·TB × 2) 출력 10개. 새로 생성하지 않았다
- 생성 부분: 출력 음에서 프라이머 토큰 음을 (pitch, onset) 다중집합으로 지운 나머지
- 이벤트: 30 ms 안에 시작한 음들을 하나의 화음 이벤트로 묶는다
- **루프 정의(정정, 아스트라 #198):** 30 ms로 묶은 뒤, 이벤트 i와 i+k의 **음높이 집합**이 같은 구간이 주기 k ≤ 24 이벤트로 3회 이상, 4초 이상 이어지는 것. 가장 긴 것 하나를 고른다
  - 처음에 "정확 이벤트 반복"이라고 쓴 것은 틀렸다. onset 간격, 길이, velocity는 비교하지 않는다. 같은 음높이열에 리듬만 다른 경우도 통과한다
  - 리듬도 같이 반복되는지는 따로 보고한다: 루프 구간의 이벤트 간격이 한 주기 뒤의 간격과 30 ms 안에서 같은 비율
  - 정의는 사후에 바꾸지 않았다. 이름과 설명만 바로잡았다
  - 조금씩 변하는 반복이나 의도된 오스티나토는 이 정의로 구별하지 못한다
- **마지막 음까지(정정):** 루프의 마지막 이벤트가 생성의 마지막 이벤트인지로 판정한다. 처음에는 1초 허용으로 판정해 TB-1을 "끝까지"로 잘못 셌다
- **종료 원인:** 토큰 로그를 남기지 않아 관측된 종료 원인은 **모름**이다. 10개 모두 생성 음이 338–340개라 1024토큰 길이 상한에서 끝났을 가능성이 있다는 가설만 있다(음당 약 3토큰). EOS 여부는 단정하지 않는다

- **음높이 집합 반복 루프가 있는 출력 4/10.** 그중 3개(P2-2, P3-1, TA-2)는 생성의 마지막 음까지 이어졌다. TB-1은 끝나기 0.87초 전(7이벤트)에 루프가 끊겼다
- 4개 모두 리듬도 함께 반복된다(3개 100%, TB-1 86%)
- **유형 둘**
  - 저음 붕괴(P2-2, TB-1): 맨 아래 옥타브 화음 하나(A0+A1, D1+D2+D3)를 0.1–0.2초 간격으로 반복. 평균 음높이가 54→27, 61→38로 떨어진다
  - 패턴 반복(TA-2, P3-1): 0.2초(C#4+C#5 / C#3 교대)나 1.5초(11이벤트 두 손 패턴) 단위. 음역은 거의 그대로다
- "단위 이벤트 중 프라이머에도 있는 것"은 단위의 각 이벤트를 하나씩 따로 본 소속 여부다(순서·리듬 무시). 반복 단위 자체가 프라이머에 있었다는 증거가 아니다. 저음 붕괴 2개는 단위 이벤트가 프라이머에 하나도 없었다
- 루프 진입 시점은 생성 후 2–22초로 제각각이다
- 프라이머 5개(P1, P2, P3, TA, TB)에는 이 정의의 루프가 없었다

## 해석 한계
- 10개 샘플의 관측이다. 생성 길이가 서로 달라서 같은 시간 노출 기준의 발생률로 쓰지 않는다
- 오스티나토와 결함을 저음이나 음 종류만으로 같다고 보지 않는다. 다만 사용자가 루프를 결함으로 들었다
- 원인(샘플링 퇴화, 모델 분포, 프라이머 성격)은 확정하지 않았다. "프라이머에 루프가 없었다 → 자기 강화"는 아직 인과가 아니다

## 다음 가설 하나
**한번 반복이 시작되면 모델 스스로의 출력이 그 반복의 확률을 높여 빠져나오지 못한다(자기 강화).**
- 근거(약함): 루프 3/4가 마지막 음까지 이어졌다. 저음 붕괴 2개는 단위 이벤트가 프라이머에 없었다. 프라이머에는 이 정의의 루프가 없었다
- 새 생성 없이 시험하는 방법: `LOOP_TF.md`(사전 등록). 관측 경로의 확률 상승만으로는 인과를 입증할 수 없어서, 같은 진입 prefix에 반복 단위 0/1/2/4회와 같은 길이의 대조 문맥을 짝지어 비교한다(아스트라 #198)
- 이 가설이 맞아도 해법(반복 패널티, 짧은 블록, 외부 입력으로 끊기)을 바로 성공으로 등록하지 않는다

- 실제 비밥 낮은 음 통계(train 60곡, 탐색). 오른손 내성과 워킹 라인이 섞인 proxy라 손 분리 정답은 아니다

  - 곡별 velocity 표준편차 p50 7.7
  - 길이 p10–p90 0.1–1.15초
  - 연속 hit 평균 음높이 이동 p50 3반음
- 실제 데이터에는 박 그리드가 없다. 그래서 박 위치 분포는 실제와 비교하지 않는다. 생성 쪽 그리드는 알기 때문에 코드 교체 시점, 반복, 충돌은 자동으로 검사한다

## 지표
- 코드 정렬: 코드가 바뀔 때마다 첫 박 안에 3음과 7음을 담고 코드 밖 pc(9음 허용)가 없는 hit이 있는 비율
- 보이싱 이동 p50: 연속 hit의 위쪽 음(≥ C3) 평균 음높이 이동
- 같은 마디 리듬이 연속되는 최대 길이
- velocity 표준편차, 초당 hit
- 솔로 충돌: 컴핑 음 시간 중 같은 음 또는 반음·장7도 관계의 솔로 음과 겹친 비율. 모든 반음을 금지하지는 않는다. 위험 지표다

## 판정 (실행 전 고정)
- **V 통과 조건**(6회 평균. 리듬 연속은 최댓값)
  1. 코드 정렬 = 1.0
  2. 보이싱 이동 p50 ≤ 3반음
  3. 같은 마디 리듬 연속 ≤ 2
  4. velocity 표준편차 3–10
  5. 초당 hit 1.0–3.7
  6. 솔로 충돌 ≤ F + 0.02
- **게이트 타당성:** R은 코드 정렬 < 1.0이거나 보이싱 이동 > 3 중 하나를 반드시 실패해야 한다. R이 다 통과하면 게이트가 무력하다는 뜻이므로 통과를 주장하지 않는다
- 통과하면 런타임에 `--comp-style varied`로 연결하고 회귀 검사를 한다(기본값을 바꿀지는 그다음에 정한다). 미달이면 기록하고 figure와 파라미터는 다시 고르지 않는다
- 통과해도 "기계적이지 않다"거나 "듣기 좋다"는 인증이 아니다. 명백한 기계성(고정 리듬, 고정 세기, 근음 위치 점프)이 줄었는지만 기록한다

- **사후 기술통계(코드가 바뀌는 지점만, 판정에는 안 씀):** 보이싱 이동

# 자연 문맥에서도 구절을 안 이어 쓰는 이유 — 디코딩 날카로움 진단 (사전 등록)

작성 2026-10-02. 이슈 #1600. 판정 규칙은 실행 전에 고정했다. 독립 리뷰(Astra)는 사용자 지시로 나중에 일괄로 받는다. `musical_quality_verified: false`.

## 배경
- #1597: 학습 분포와 같은 자연 문맥(앞 256토큰)을 줘도 자유 생성의 음정 재등장(IR)은 0.007이었다. 실제 이어지는 구간은 0.052다. 리듬 포함 재등장(VR)은 0이었다
- 가능도로는 모델이 그 곡의 앞 문맥을 쓰고 있었다(M − N > 0)
- 그래서 디코딩이 원인일 수 있다. 무작위 샘플링(temperature 1.0, top-k 32)이 앞 문맥에 맞는 높은 확률의 반복 대신, 다양한 다른 음을 고르게 만들 수 있다

## 질문 (하나)
같은 위치·같은 자연 문맥에서 temperature를 낮추면, 자유 생성의 IR이 실제 연주 수준에 가까워지는가. 기계적 반복이나 앞부분 복사로 점수가 오르는 경우는 빼고 본다.

## 고정 설계
- 위치·target·자연 문맥: #1597과 같은 규칙과 같은 위치(`scripts/context_mismatch_diag.py`의 `pick_positions`, N primer)
- 모델: Tatum 완성, 공통 base. 멜다우는 holdout 2곡에서 기술 통계만 낸다
- 데이터: 진단용 val12(파이프라인 확인만), 평가용 fresh12(판정. 최종 평가에 한 번 쓴 재사용 셋)
- 디코딩 격자(고정): temperature **1.0 / 0.8 / 0.6**. 나머지는 top-k 32, top-p 0.95, grammar mask, 2초 목표 길이로 둔다. 위치마다 seed 2개를 쓰고, 세 온도가 같은 seed를 쓴다
- 지표(생성과 실제 이어지는 구간에 똑같이 적용, 앞 8초 윗선율 기준)
  - IR(주지표), VR, XR(정확 재등장)
  - 반복률: 1 − 서로 다른 창 수 / 창 수(기계적 반복 감시)
  - 복사 플래그: 앞 8초와 같은 음높이·IOI의 연속 5음
  - 음 수, 검증 통과율
- 집계: 곡별 비율의 합을 먼저 낸다(유효 출력만). 곡 단위 bootstrap 95% CI를 쓴다

## 판정 (평가용, 모델별, 실행 전 고정, 기준은 실제 연주 값으로 정함)
- **디코딩으로 설명됨:** 0.8 또는 0.6 중 하나라도 다음을 모두 충족
  1. IR(T) ≥ 0.5 × 실제 IR(곡 평균)
  2. IR(T) − IR(1.0)의 곡 CI 하한 > 0
  3. 보호 조건
     - 반복률 ≤ 실제 반복률 + 0.15
     - 복사 플래그 비율 ≤ max(0.25, 실제 복사 비율 × 2)
     - 검증 통과율 ≥ 0.9
- **디코딩만으로는 설명 안 됨:** 0.8과 0.6 모두 위 조건을 충족하지 못함. 이 격자 안에서 날카로운 디코딩이 격차를 메우지 못한다는 뜻이다
- 학습 부족은 판정하지 않는다. 어떤 결과도 새 학습이나 런타임 기본값 변경의 자동 근거가 아니다
- 이 단위에서 격자나 기준을 다시 탐색하지 않는다

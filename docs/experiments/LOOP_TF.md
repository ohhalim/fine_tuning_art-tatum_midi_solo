# 반복 문맥이 다음 반복 확률을 올리는가 — teacher forcing 짝 비교 (사전 등록, 탐색)

작성 2026-10-08. 선행: `LOOP_DIAG.md`. 아스트라 #198 설계. 새 생성, 튜닝, 해법 등록은 하지 않는다. `musical_quality_verified: false`.

## 질문 (하나)
루프 진입 직전까지의 같은 연주 뒤에 반복 단위를 n번 둔 문맥과, 같은 길이의 다른 음악을 둔 대조 문맥을 비교한다. 바로 다음에 오는 같은 반복 단위(후보)의 점수가 반복 문맥에서 더 높은가.

## 대상
LOOP_DIAG에서 찾은 루프 4개(P2-2, P3-1, TA-2, TB-1) 전부. 탐색으로 표시한다.

## 입력 구성 (MIDI에서 만든 뒤 Aria 토크나이저로 토큰화)
- 원래 샘플링된 토큰은 기록하지 않았다. 그래서 출력 MIDI를 다시 토큰화한 **재구성 입력 진단**이다. 재토큰화가 원래 토큰과 같다고 가정하지 않는다
- 기호
  - t_L: 루프 시작 이벤트의 시각(출력 시간축)
  - P: 주기. 루프 시작 이벤트에서 k이벤트 뒤 이벤트까지의 시간
  - U: 출력에서 [t_L, t_L + P) 구간의 음, 즉 한 주기
- prefix: 출력에서 onset < t_L인 모든 음(프라이머 + 루프 전 생성)
- 반복 조건 R_n: prefix + U를 j·P만큼 옮긴 사본 n개(j = 0…n−1) + 후보(U를 n·P만큼 옮긴 것)
- 대조 조건 C_n: prefix + 채움 + 같은 후보. 채움은 출력에서 t_L 바로 앞 n·P초 구간의 음을 n·P만큼 뒤로 옮긴 것이다. 길이는 같고 반복 단위는 아니다
- n ∈ {0, 1, 2, 4}. n = 0이면 R과 C가 같아 기준이 된다
- 후보의 시각은 같은 n에서 R과 C가 같다. 그래서 후보 토큰열도 같다
  - n이 다르면 후보의 절대 시각, 위치, 문맥 길이가 달라진다. n 사이의 비교로 인과를 단정하지 않는다
- 문맥 토큰열이 전체 토큰열의 접두사인지 확인한다. 접두사가 아니면 그 조건을 기록하고 점수를 내지 않는다

## 점수
- 후보 토큰 구간: 전체 토큰열에서 문맥 토큰열 뒤에 오는 모든 토큰. 5초 시간 토큰이 있으면 포함한다
- **원 확률(temp 1, 필터 없음):** 후보 토큰들의 joint log 확률과 토큰당 평균
- **샘플러 관점(temp 0.98, min_p 0.035):** 후보 토큰마다 min_p 필터를 통과하는지(확률 ≥ 0.035 × 그 위치 최대 확률), 통과 비율. 필터가 탈출 후보를 지우는지는 별개 가설이라 여기서는 보고만 한다
- 길이가 다른 후보의 확률을 서로 직접 비교하지 않는다. 같은 루프 안에서 R_n 대 C_n의 차이만 본다

## 보고와 해석 범위
- 루프마다 n별 R_n·C_n의 joint·평균 log 확률, 차이(R − C), 필터 통과 비율
- 결론은 "반복 문맥에서 후보 점수가 대조보다 높았다/아니었다"까지다
  - 높아도 자기 강화의 인과 증거가 아니다. 원래 반복에 맞는 문맥이었을 수 있고, 살아남은 경로라는 선택 편향도 있다
  - 높지 않아도 모델의 반복 취약성을 반증하지 않는다. 처음부터 높았거나 샘플러 효과일 수 있다
- 이 한 단위로 끝낸다. 결과에 따라 해법을 바로 등록하지 않는다

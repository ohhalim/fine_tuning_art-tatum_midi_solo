# 같은 예산 대조 어댑터 설계 (#1733) — 학습 없음

Mehldau Aria LoRA(#1726)는 CE를 내렸다. 학습에 쓰지 않은 Mehldau val에서 −0.297, 다른 피아니스트 probe에서 −0.283이다. 차이가 −0.014뿐이라, 이 개선이 **Mehldau 특화**인지 **PiJAMA 피아노 자료·창 형식에 대한 일반 적응**인지 가려낼 수 없다.

이 문서는 그 질문에 답할 대조 실험의 설계다. **학습은 아직 하지 않는다.** 실행 여부와 세부는 아스트라와 확정한 뒤 별도 사전 등록으로 고정한다.

## 질문 (한 가지)

같은 예산·같은 전처리로 Mehldau가 아닌 피아노 자료에 학습한 대조 어댑터 C와 비교하면, Mehldau 어댑터 M은 Mehldau val에서 C보다 더 내려가는가? probe에서는 두 어댑터가 비슷한가?

## 고정하는 것 (#1726 그대로)

- frozen `model-gen.safetensors`. M은 기존 `lora_u128.pt`를 그대로 쓴다(다시 학습하지 않음)
- LoRA r16, alpha 16, `mixed_qkv`·`att_proj_linear` 16층, A seed 0, B 0
- Adam lr 1e-4, 128 update
- 매 update `random.Random(0)`으로 녹음을 균등하게 고르고, 그 녹음의 창을 균등하게 고른다
- 창 규칙: 음 경계에서 자르고 화음은 쪼개지 않는다. 첫 onset을 0으로 옮겨 재토큰화하고 왕복 검사를 한다. `<D>`·`<E>`를 빼고, 32음 미만 꼬리는 버린다. loss는 `<S>` 다음부터
- 평가셋: Mehldau val(12녹음, 80창), probe(4명 20곡, 144창). #1726 manifest 그대로
- **test 봉인 유지.** #1726 개발 미달이라 열지 않는다. 이 실험도 열지 않는다

**M의 실제 학습량** (`train_report.json`의 `train_steps`): 128 update, 서로 다른 녹음 48개, loss 대상 토큰 119,650개(update당 평균 935). 학습 녹음은 50개(studio 13 / live 37), 창 597개, 창 길이 중앙값 1,022토큰.

## 대조 후보 (기존 PiJAMA `midi` 트리 안, 다운로드 없음)

공통 제외: Mehldau, Tatum, probe 4명(Hiromi, Ted Rosenthal, James Williams, Alan Pasqua). 그리고 Mehldau 72곡과 정규화 제목이 같은 녹음. 같은 곡이 섞이면 스타일이 아니라 곡 내용으로 Mehldau val CE가 내려갈 수 있기 때문이다.

남는 자료: **115명, 2,485녹음(studio 1,789 / live 696)**. live가 3개 이상 남는 피아니스트는 50명이다.

| 후보 | 구성 | 장점 | 한계 |
|---|---|---|---|
| **C-pool (권장)** | 여러 피아니스트에서 50녹음(studio 13 / live 37). 한 사람당 최대 1녹음, `Random(0)` 층화 추출 | "일반 피아노 적응"을 가장 직접 잰다. 특정 연주자 스타일이 섞이는 것을 최소화한다 | 녹음 50개가 50명에게서 와서 연주자 다양성이 M보다 훨씬 크다. 그 다양성 자체가 다른 적응을 만들 수 있다 |
| C-hersch | Fred Hersch 50녹음(남은 65개 중 studio 13 / live 37 추출) | 한 사람이라 M과 구조가 같다. Hersch 자신의 held-out으로 대칭 비교(M→Hersch, C→Mehldau)도 할 수 있다 | Hersch 고유의 스타일 적응이 섞인다. Mehldau와 비슷한 시대·성향이면 차이가 작게 나와 특화를 과소평가할 수 있다 |

- 어느 쪽이든 학습 녹음 수, studio/live 구성, 창 규칙, update 수, 샘플링 규칙을 M과 같게 맞춘다
- 창 길이는 같은 규칙에서 자연히 비슷해진다(대부분 1,024 근처). 실제 loss 대상 토큰 수는 실행 뒤 M의 119,650과 나란히 보고한다. 맞추려고 창을 골라내지 않는다
- 제목 기준 중복 제거라 다른 제목의 같은 곡, 다른 전사의 같은 녹음은 남을 수 있다. 이 한계는 그대로 적는다

## 평가 — 차이의 차이

base CE는 #1726 보고서에 이미 있다(같은 창, 같은 코드). C 평가만 새로 한다.

- 녹음 r마다 ΔCE(어댑터) = CE(어댑터) − CE(base). 녹음 안은 토큰 가중, 요약은 녹음 평균(#1726과 같음)
- **D_val** = 평균 ΔCE_M(val) − 평균 ΔCE_C(val). 음수면 Mehldau val에서 M이 C보다 더 내려갔다는 뜻이다
- **D_probe** = 평균 ΔCE_M(probe) − 평균 ΔCE_C(probe)
- **특화 지수 S** = D_val − D_probe
- 녹음별 짝 비교: val 12녹음 중 ΔCE_M < ΔCE_C인 수, probe 20곡 중 같은 수
- 토큰 종류별(pitch / onset / dur / `<T>`), pitch 주변, velocity|pitch도 같은 식으로 낸다. #1726에서 dur 몫이 가장 컸으므로, 특화가 있다면 어느 성분인지 본다

**읽기 규칙 후보** (실행 전 아스트라와 확정. 결과를 보고 바꾸지 않는다)
- 특화 있음: D_val ≤ −0.03 nat/token이고, val 12녹음 중 9개 이상에서 M이 C보다 낮다. 그리고 |D_probe| ≤ 0.02
- 특화 없음: |D_val| ≤ 0.02이고 val에서 M이 C보다 낮은 녹음이 8개 이하
- 그 밖은 불분명
- 이 숫자들은 공학적 임시 기준이다. 아래 seed 변동을 재지 않으면 0.02~0.03 차이가 잡음보다 큰지 알 수 없다

## 꼭 정해야 할 것 — seed 변동

M과 C를 seed 하나씩만 학습하면, D_val이 작을 때 그게 실제 차이인지 학습 잡음인지 구별할 수 없다. 선택지는 셋이다.

1. **seed 1개씩(최소):** M은 기존 것을 쓰고 C만 학습한다. 비용이 가장 적다. 대신 |D_val|이 작으면 "불분명"으로 끝날 가능성이 크다
2. **seed 3개씩(권장 검토):** LoRA 초기화·샘플링 seed {0, 1, 2}. M은 seed 1, 2를 새로 학습한다(기존 seed 0 유지). seed 사이 변동으로 D_val의 잡음 범위를 잰다
   - 이것은 실패 뒤 seed 탐색이 아니다. 실행 전에 세 개를 고정하고 전부 보고한다
   - 다만 Mehldau 학습을 더 하는 것이므로 아스트라 확인이 필요하다
3. seed 1개씩 하되, 같은 C 자료에서 창 샘플링만 바꾼 반복으로 잡음을 근사한다. 2보다 싸지만 M 쪽 변동은 못 잰다

## 생성 조건 비교 (보조)

- #1731과 같은 공통 형식 마스크, 같은 4 prompt × seed 1, 2. C만 새로 8개 생성한다. base·M은 #1731 결과를 쓴다
- 비교 대상은 마스크 의존(개입 수, 상태별 개입, 마스크 전 비허용 질량)이다. M에서 본 "dur 자리 문법 밖 질량"이 C에도 있으면 Mehldau 고유가 아니라 이 적응 설정 공통이라는 뜻이다
- 결함 지표는 기술만 한다. 점수로 쓰지 않는다
- 렌더와 블라인드 세트는 만들 수 있다. 청취는 선택이고, 없으면 선호는 미확인이다. CE 차이로 청취상 스타일 성공을 주장하지 않는다

## 비용 (#1726·#1731 실측 기준 추정)

| 단계 | seed 1개 | seed 3개 |
|---|---|---|
| C 자료 만들기(창 자르기, 왕복 검사) | 수 분 | 같음 |
| 학습(128 update, 회당 약 120초) | C 1회 | C 3회 + M 2회 |
| 평가(val·probe, 회당 약 3분) | 1회 | 5회 |
| 생성(마스크, 8개, 약 8분) | 1회 | C seed 0만 |

- 발열: #1731 생성 중 GPU 80~82°C, 열 압력이 Heavy까지 오른 적이 있다. 실행 중 열 압력은 기록만 하고, 사용자 지시 없이 멈추지 않는다
- 새 유료 자원, 외부 다운로드, 공개 업로드 없음. 기존 PiJAMA 로컬 자료(CC-BY-NC-4.0)만 쓴다

## 이 설계가 답하지 못하는 것

- C-pool은 연주자 다양성이, C-hersch는 Hersch 고유 스타일이 섞인다. 어느 쪽도 "순수한 일반 적응"은 아니다
- 제목 기준 중복 제거의 한계: 다른 제목의 같은 곡은 남을 수 있다
- LoRA 설정·학습량은 하나뿐이다. 더 길게 학습하면 특화가 나타나는지는 이 설계로 모른다
- CE 차이는 청취상 스타일과 같지 않다. 특화가 나와도 "Mehldau처럼 들린다"는 주장은 하지 않는다

## 아스트라와 정할 것

1. 대조 후보: C-pool(권장) 또는 C-hersch
2. seed 변동: 선택지 1, 2, 3
3. 읽기 규칙 숫자
4. 생성 조건 비교를 포함할지

정해지면 C 자료 manifest와 runner를 사전 등록으로 고정하고, 그때 학습한다.

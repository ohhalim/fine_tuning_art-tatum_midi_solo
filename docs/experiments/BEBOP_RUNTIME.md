# 비밥 어댑터 런타임 연결 (사전 등록)

작성 2026-10-02. 이슈 #1620. 판정 규칙은 실행 전에 고정했다. 독립 리뷰는 사용자 지시로 나중에 일괄로 받는다. `musical_quality_verified: false`.

## 근거
- #1618: 비밥 오른손 어댑터는 실제 오른손 문맥을 줬을 때 밀도·쉼·프레이즈가 실제와 비슷했다(초당 4.56음 vs 4.06)
- 런타임은 실제 오른손 문맥이 없다. 반 마디마다 코드 primer만 보고 생성한다. 같은 성질이 여기서도 유지되는지는 따로 재야 한다
- 사용자 요청: 솔로는 릭처럼, 너무 빠르지 않게. 컴핑은 짧고 깔끔하게 지금 무슨 코드인지만 알려 준다

## 변경
- `play_personalized.py --preset bebop`, `fl_live.py --preset bebop`
- `--comp`: 근음(C2–G2) + 3음·7음(E3–Eb4)을 1박과 3박 &에 0.25초 짧게 친다(velocity 56). 이전의 모델 저음역 컴핑은 쓰지 않는다
- `--solo-line`: 모델 출력에서 50 ms 묶음마다 가장 높은 음만 남긴다(기존)

## 실행
- 진행 3개 × seed 42/43: ii–V–I C(16마디, 128 BPM), F 블루스(12마디, 120 BPM), C 단조 ii–V–i(16마디, 128 BPM)
- 비교군: `--preset bebop` vs `--preset tatum`, 둘 다 `--solo-line`, 나머지 런타임 기본값(T 1.0)
- 측정은 `--comp` 없이 한다. 컴핑 음이 맨 위 선율 측정에 섞이지 않게 하려는 것이다. 청취용 렌더는 `--comp`를 켜고 따로 만든다
- 스크립트: `scripts/runtime_rh_check.py`

## 지표 (실제로 재생된 맨 위 선율)
- 초당 음 수, 쉼(≥ 0.3초) 시간 비율, 쉼 사이 프레이즈 길이 중앙값
- 솔로 코드톤 비율(재생 시점 코드의 구성음)
- 보고만: 프레이즈 끝 음의 코드톤 비율(D2에서 좋았던 "어느 화성에서 무엇을 말하는지" 성질), 대체 패턴 수, deadline miss

## 판정 (실행 전 고정, 기준은 data/bebop_rh train 중앙값: 초당 3.71음, 쉼 7.56%, 프레이즈 16음)
- **통과:** bebop 6회 합산이 모두 충족
  1. 초당 음 수가 데이터의 0.67–1.5배다(2.49–5.57)
  2. 쉼 시간 비율이 데이터의 0.5배 이상이다(≥ 3.78%)
  3. 프레이즈 길이 중앙값이 데이터의 2배 이하다(≤ 32)
  4. 솔로 코드톤 비율이 Tatum 런타임(같은 조건) − 0.03 이상이다
  5. 대체 패턴 0
- 통과하면 FL 문서에 `--preset bebop`을 기본 권장으로 쓰고 청취를 요청한다. 미달이면 기록하고 이 단위에서 디코딩 설정을 다시 탐색하지 않는다

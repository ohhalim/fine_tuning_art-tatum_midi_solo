# Aria MLX 생성 중간 되돌리기·첫 호출 비용·송출 계약 (#1739) — 사전 등록

#1737에서 로컬 Aria MLX의 KV 캐시 이어 생성이, 시험한 토큰열에서 처음부터 계산한 것과 같다는 것을 확인했다(토큰당 약 11 ms). 남은 것은 세 가지다.
- 되돌리기는 prompt 끝으로만 시험했다
- 새 길이를 처음 계산할 때 튀는 값(0.18~0.85초)이 있었다
- 실시간에서 무엇을 확정으로 내보내고 무엇을 버릴지 규칙이 없다

이 문서는 그 셋을 다루는 기반 점검이다(아스트라 #1738 재리뷰 합의). 소리나 코드 제어를 개선하는 실험이 아니다.

## 질문

1. 생성 중간 위치로 되돌려 짧거나 긴 다른 토큰열을 이어 넣어도, 처음부터 계산한 것과 같은가?
2. 되돌린 뒤 캐시에 남아 있는 취소된 토큰이 이후 계산에 보이지 않는가?
3. 처음 쓰는 길이의 첫 호출 비용은 얼마인가? 같은 길이의 두 번째 호출(warm)과 나눠 잰다
4. 확정 송출, 미확정 생성, 울리는 음의 note-off 책임을 어떤 규칙으로 정하나?

## 고정 조건

#1737과 같다. 로컬 `t3_aria`(커밋 c2f67bc, mlx 0.25.2, 로컬 `max_kv_pos` 패치), `model-gen.safetensors`, float32 가중치·캐시. 토큰열은 #1731 마스크 생성의 A(prompt 0 + base seed 1), B(prompt 0 + base seed 2), 각 614토큰. 캐시 용량은 모든 검사가 쓰는 최대 위치 + 1로 미리 계산하고, 범위 밖 호출은 forward 전에 거절한다.

## 검사와 기준 (실행 전 고정)

**R 되돌리기 (`scripts/aria_mlx_rollback_smoke.py`)**
- 캐시에 A 전체(위치 0~613)를 채운다
- 되돌릴 위치 R ∈ {P+64, P+256, P+448}(P = prompt 길이 102), 대체 길이 k ∈ {8, 128}, 6가지 조합이다
- R부터 B의 생성 토큰 k개를 한 번에(chunk) 써 넣는다. 이어서 저장된 B 토큰 16개를 하나씩 decode한다
- 같은 토큰열 `A[:R] + 대체 + 이어진 16토큰`을 새 캐시에 한 번에 넣은 결과와 비교한다
- **기준:** 써 넣은 모든 위치에서 top-1이 같고, 최대 |logit 차| ≤ 1e-3
- 새 끝 뒤에 A의 옛 토큰이 남아 있는 조합(5개)은 "취소된 토큰이 보이지 않는다"는 검사도 된다. 조합마다 남은 칸 수를 기록한다. R = P+448, k = 128 조합은 옛 칸이 남지 않는다

**F 첫 호출 비용**
- 프로세스가 시작한 뒤 다른 forward보다 먼저 잰다
- 처음 쓰는 prefill 길이 96, 160, 224, 288, 352, 416, 480, 544마다 첫 호출과 같은 길이의 두 번째 호출 시간을 잰다
- 첫 길이(96)의 첫 호출은 프로세스 첫 forward라 따로 표시한다
- 256토큰 prefill 뒤의 첫 한 토큰 decode와 그다음 decode도 잰다
- 보고만 하고 합격선은 두지 않는다

## 실시간 송출 계약 (설계. 이번 단위에서는 구현하지 않는다)

용어
- **확정 구간:** 런타임이 MIDI 스케줄러에 넘긴 토큰. 이미 울렸거나 울릴 예정이다
- **미확정 구간:** 생성했지만 아직 넘기지 않은 토큰
- **커서:** KV 캐시에 마지막으로 써 넣은 위치

규칙
1. **확정 단위는 완결된 음이다.** 피아노 음 토큰, onset, dur 세 개가 다 있어야 확정한다. 음 중간(note-on만 확정되고 dur는 미확정)에서 끊지 않는다. 그래야 확정한 모든 음의 note-off 시각이 정해져 있다
2. **확정 구간은 바꾸지 않는다.** 코드 입력이 와도 이미 넘긴 음은 고치지 않는다. 그래서 반응은 확정 지평(예: 1박) 뒤부터 나타난다. "첫 박 패치"처럼 확정된 음을 바꾸는 방식은 쓰지 않는다(아스트라 #1736 H2)
3. **입력이 오면 미확정 구간을 버린다.** 커서를 확정 구간의 끝으로 되돌리고, 그 뒤에 새 입력(제어 토큰 등)을 써 넣은 다음 다시 생성한다. 버린 칸은 `max_kv_pos`로 가려져 보이지 않는다(검사 R에서 확인)
4. **note-off는 스케줄러가 책임진다.** 확정한 음의 note-off는 확정할 때 정해진 시각에 스케줄러가 보낸다. 모델이나 캐시가 되돌려져도 영향을 받지 않는다. 버린 미확정 음은 보내지 않았으므로 짝 없는 note-off도 생기지 않는다
5. **되돌릴 때 문법 상태도 함께 되돌린다.** 확정 구간 끝의 문법 상태(음 사이/onset/dur, 구간의 마지막 onset, `<T>` 구간 번호)를 저장해 두고, 형식 마스크를 그 상태에서 다시 시작한다
6. **어댑터를 바꾸면 전체 reset이다.** 이전 어댑터로 계산한 KV는 새 어댑터에서 유효하지 않다. 문맥 전체를 새 어댑터로 다시 prefill하고, 미확정 구간은 모두 버린다. 확정 음의 note-off는 규칙 4대로 스케줄러가 계속 책임진다. 교체는 프레이즈 경계에서 한다. 이번 단위에서는 구현하지 않는다
7. **멈추면 모든 음을 끈다.** 정지나 오류가 나면 스케줄러가 울리는 음 전체에 note-off를 보낸다(all-notes-off)
8. **캐시 용량을 넘기 전에 문맥을 줄인다.** 커서가 용량에 가까워지면 오래된 문맥을 잘라 처음부터 다시 prefill한다. 이때 F에서 잰 새 길이 첫 호출 비용이 생기므로, 자르는 길이를 몇 개로 고정해 미리 데워 둔다(warm-up)

## 하지 않는 것

착지 바이어스, 후보 재순위, CFG, 양자화, 새 학습, 다운로드, 런타임 구현, 키 입력부터 소리까지의 지연 주장, 소리·제어 개선 주장.

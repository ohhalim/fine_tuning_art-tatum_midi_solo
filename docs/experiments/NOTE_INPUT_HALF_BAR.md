# 반 마디 블록에서 키보드 음 입력 반영 — 기능 확인 (사전 등록)

작성 2026-09-29. 이슈 #1538. `style_verified: false` · `musical_quality_verified: false` · 가상 CoreMIDI 포트, 실물 키보드 없음

**이 절은 실행 전에 작성했다.**

## 질문
프리셋은 반 마디 블록(#1532)을 쓰고, 반 마디마다 자기 입력 스냅샷(최근 4초)의 음을 코드 primer에 넣는다. 지연은 PC 메시지로만 쟀다. 실제 음 입력이 (1) 세션을 깨지 않고, (2) 생성에 실제로 쓰이는지 확인한다.

## 조건
- `run_live_select_probe.py --notes`(note_on 뒤 0.25초에 note_off). PC는 보내지 않는다
- 런타임은 쌍 S 설정이다(`--adapter-control`이 붙지만 PC가 없으므로 Tatum 완성만 연주한다). `--half-bar-blocks`, 128 BPM, 16마디, seed 42/43/44
- 음: 실행 후 14.0 / 14.3 / 14.6 / 14.9 / 15.2초에 C5 E5 G5 B5 D6(72, 76, 79, 83, 86)
- 비교 기준: 같은 seed의 무입력 반 마디 블록 실행(`outputs/half_bar/sweep/tatum_final/bpm128_seed*`, #1532)

## 판정 (모두 충족하면 "음 입력 경로 동작"으로 기록)
1. 3회 모두 완주, fallback 0, 미스 0
2. 입력 스냅샷에 음이 없는 블록은 무입력 실행의 같은 반 마디와 전부 동일하다(시드 결정성)
3. 음이 들어간 블록 중 적어도 하나는 무입력 실행과 다르다(입력이 실제로 primer에 쓰임). 세 실행 모두에서 확인한다
4. 첫 입력 블록의 `input_to_block_start_ms`(스냅샷의 최신 입력 → 블록 시작)를 보고한다(기준 없음)

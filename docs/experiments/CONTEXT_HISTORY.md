# 런타임이 앞 내용을 기억하게 — 다중 블록 이력 문맥 (청취 비교)

작성 2026-09-29. 이슈 #1572. `style_verified: false` · `musical_quality_verified: false`

## 배경
- 사용자 청취(Tatum 런타임, 128·90 BPM)
  - "불협화음이 많고 막 누르는 것 같다"
  - "기승전결이 없다"
  - "말할 때 어순이 이어지지 않는 것 같다"
- 구조상 이유: 반 마디마다 코드 음 10토큰만 보고 새로 생성하고, 앞에서 친 내용은 보지 않는다
- 예전 문맥 연결 시험(#1505, #1513)은 직전 블록 꼬리 32토큰만 이었다. 코드톤 수치가 떨어져서 닫았고, 귀로는 판단하지 않았다

## 변경 (opt-in)
- `--context-history`(`--context-carry-tokens N`과 함께): 지금까지 연주한 모든 유효 블록을 이어 붙인 이력의 마지막 N토큰을 primer에 넣는다
  - 일찍 끝난 블록은 시간 토큰으로 창 끝까지 채운다(`pad_to_duration`). 그래야 이력의 시간이 실제와 맞는다
  - 이력은 최대 2048토큰까지 보관한다
- 순서
  - `--context-carry-position before`: [이력][코드 음][생성]
  - `--context-carry-position after`: [코드 음][이력][생성]

## 청취 후보 (Tatum 완성, 반 마디 블록, ii–V–I C, 16마디, 128 BPM, seed 42, N = 256, max-sequence 512)
| | 순서 | 음 수 | 코드톤 | 마디 경계 도약 중앙값 | fallback | 생성 p95 ms |
|---|---|---|---|---|---|---|
| A 지금 런타임 | 이력 없음 | 396 | 0.513 | 20 | 0 | 433 |
| E | 이력 → 코드 | 440 | 0.505 | 19 | 0 | 402 |
| F | 코드 → 이력 | 405 | 0.422 | 19 | 4 (생성 지연, 예산 469 ms 초과) | 486 |

- 판정은 사용자 청취로 한다: A, E, F 중 어느 쪽이 이어지게 들리는가, 코드와 어울리는가
- 청취 페이지: https://claude.ai/artifact/KzrGXUMDKEArsP9CSe7nzw (비공개)
- 한 seed, 한 진행이다. 청취 결과가 나오기 전에는 기본값을 바꾸지 않는다

## E를 프리셋 기본값으로 올릴지 — 견고성 확인 (사전 등록, 실행 전)
- 사용자 응답 "해보자"를 E로 진행하자는 뜻으로 받았다. F는 코드톤 하락과 fallback 때문에 제외한다. 청취로 E가 A보다 낫다는 판정은 아직 없다
- 조건: 반 마디 블록, E 설정(`--context-carry-tokens 256 --context-history --context-carry-position before --max-sequence 512`)
  - 모델: Tatum 완성, 멜다우 #1497
  - 진행: ii–V–I C(16마디, 128 BPM), F 블루스(12마디, 120 BPM), 마이너 ii–V–i C(16마디, 128 BPM)
  - seed 42, 43 → E 12회. 빠른 템포 확인으로 Tatum ii–V–I 200 BPM × 2회를 더한다
  - A(현재 기본) 기준: seed 42는 쇼케이스 실행을 쓰고, seed 43은 새로 잰다(6회)
- **판정(모두 충족하면 프리셋에 E를 기본으로 넣고 끄는 옵션을 둔다)**
  1. E 14회 모두 fallback 0(미스는 보고만)
  2. 코드톤 평균: E가 짝지은 A보다 0.03 이상 낮지 않다(모델·진행·seed로 짝을 짓는다)
- 통과하더라도 청취 확인용으로 멜다우 E 샘플을 페이지에 추가한다

### 결과 — 기준 1·2 미달, **E를 기본값으로 올리지 않는다**
원시값: `docs/experiments/context_history/robustness.json`. 측정 중 부하 평균은 약 3.8–5.5였다.

| 기준 | 결과 |
|---|---|
| 1. E 14회 fallback 0 | **7블록** ✗ — Tatum 블루스 s42 1·s43 1, 마이너 s43 2, ii–V–I 200 BPM s42 3. 문맥이 길어져 생성이 시작 예산을 넘었다(A도 Tatum 블루스 s43에서 1블록) |
| 2. 코드톤: E가 짝지은 A보다 0.03 이상 낮지 않음 | 평균 차이 **−0.040** ✗ — 짝별 −0.155 ~ +0.074. 12쌍 중 9쌍에서 낮았다 |

- 멜다우는 E에서 음 수가 크게 늘었다(ii–V–I 248 → 370, 마이너 269 → 378)
- 이 확인은 **비용**(코드톤, 지연)만 잰다. 사용자가 지적한 "이어지느냐"는 수치로 잡히지 않는다
- 그래서 판단에 필요한 청취 쌍(Tatum A/E, 멜다우 A/E)을 청취 페이지에 올렸다
- `--context-history`는 opt-in으로 브랜치에만 남긴다. 청취에서 E가 이어지게 들리면, 그때 비용(시작 예산, 문맥 길이, 코드 제시 방식)을 줄이는 작업을 한다

## 정정 (Astra 재리뷰 @0696d103)
- **M3 — 이력이 "실제로 연주된 것"이 아니었다**
  - 결함: 생성 직후 토큰을 쌓았다. 그래서 유효하지만 늦어 버려진 블록이 들어갔고, 대신 연주된 fallback 블록과 그 시간은 빠졌다. `pad_to_duration`은 블록마다 937.5 → 930 ms로 잘라 시간이 밀렸다. 2048 상한은 velocity 상태를 잃을 수 있었다
  - 수정(`PlayedHistory`): 블록은 스케줄러가 가져간 뒤에만 이력에 들어간다. `adoption_snapshot` 기준으로 채택된 모델 블록, 아니면 실제로 연주된 fallback 블록이다(`BarBlockProducer.fallback_for`). 연주된 이벤트를 토큰으로 바꾸고(`block_to_notes`), 시간은 블록 격자에 누적 정렬한다. 상한은 velocity를 보존해 자른다
  - 회귀 테스트: 늦어서 버려진 블록 대신 fallback이 이력에 들어간다. 판정 전 블록은 기다린다. 40블록 누적 시간이 정확히 37.5초다
- **M4 — 지원하지 않는 경로에서 조용히 무시됨**
  - 수정: `--context-history`는 `--half-bar-blocks`가 필요하다. `--context-carry-tokens`는 sub-block 경로(`--chord-blocks-per-bar 2`)가 필요하다. 아니면 오류를 낸다
- 수정 후 스모크(Tatum, ii–V–I, seed 42): 경계/내부 1.011(A 1.596), 동기 재사용 0.016, fallback 0
- 앞의 E 결과(청취 후보 E, 견고성, 2·3단계 E)는 고치기 전 구현으로 생성한 것이다

## 정정 2 (Astra 재리뷰 @b381b83b) — 이력 시간축
- **잔여 결함:** 블록마다 따로 인코딩해서 이벤트 간격마다 10 ms 반올림이 들어갔다. padding은 모자란 시간만 더할 수 있었다
  - 재현: 경계까지 지속되는 음(0 → 0.9375초)을 가진 40블록은 블록마다 940 ms로 올림돼 이력이 37,600 ms가 됐다(격자 37,500 ms)
  - 앞 정정의 "누적 시간 정렬, 드리프트 없음" 주장은 사실이 아니었다. 테스트가 0.3초에서 끝나는 음만 써서 놓쳤다
- **수정:** 모든 음 시각을 먼저 **절대 세션 10 ms 격자**에 놓고, 격자 시각의 차이로 인코딩한다. 각 블록은 누적 경계에 정확히 맞춰 끝난다. 30초 보관 범위를 두고, velocity를 보존해 상한으로 자른다
- **회귀 테스트**
  - 경계까지 지속되는 음 40블록: 옛 구현 37,600 ms, 새 구현 37,500 ms(직접 비교)
  - 촘촘한 이벤트(블록당 17음, 55 ms 간격)가 절대 격자에 놓인다
  - 빈 블록의 시간이 유지된다
  - fallback 대체
  - 상한에서 velocity를 보존한다
  - 보관 범위로 잘라도 정렬이 유지된다
- **문구 한정(LOW):** 이력은 "실제로 전송이 끝난 것"이 아니라 **채택되거나 예약된(adopted/scheduled) 블록**이다. 블록의 미래 note-off가 포함되고, 실행이 취소되면 블록 중간에서 멈출 수 있다
- 이전 E 결과(고치기 전 두 구현)와 새 구현 결과는 섞지 않는다
- 수정 후 스모크(Tatum, ii–V–I, seed 42, 1회): 경계/내부 1.213(A 1.596), 동기 재사용 0.000, fallback 0, 미스 3(보고만 한다)
  - 앞 구현 스모크의 재사용 0.016과 다르다. 1회 값이라 비교하지 않는다

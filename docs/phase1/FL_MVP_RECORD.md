## 확인한 사실과 한계
- FL은 입력 MIDI를 포트가 맞는 채널뿐 아니라 **선택된 채널에도** 보낸다. 선택 채널의 입력 포트를 바꿔도 같았다. 그래서 되먹임 필터가 필요했다
- Claude가 보낸 합성 키 입력은 FL의 자판 기능에 먹히지 않았다. 자판 → 런타임 구간은 사용자가 직접 쳐서 확인했다(150–176번 블록에 입력 3음)
- 반영 지연은 약 1.1–1.4초다(블록 생성 전 스냅샷에서 코드를 읽음)
- 템포는 FL과 맞추지 않는다(런타임 자체 128 BPM)
- 마지막 실연결 실행은 사용자 요청으로 중간에 껐다. 그래서 결과 리포트 파일은 없고 로그만 있다(`outputs/fl_live/tatum.log`, git 미추적)

## 정정: 변환 전 원본 검증 (Astra HIGH, #1593)
- 결함: `--solo-line`/`--comp` 변환이 원본 검증보다 먼저 실행됐다. 중복 note_on·짝 없는 note_off가 있는 무효 모델 블록이 변환 후 유효해져, fallback과 유효율이 과대평가될 수 있었다(재현: `[376,60,60,349,188]`, `[376,60,349,188,188]`)
- 수정: 원본을 먼저 검증한다
  - 무효면 원본 그대로 넘겨 기존 fallback이 연주된다
  - 변환 결과도 다시 검증한다. 무효면 유효한 원본을 연주한다
  - 리포트 `solo_line_render`에 `raw_invalid` / `rendered` / `rendered_invalid`를 따로 센다
  - **이 통계는 생성 시도 기준이다. 채택된 블록이나 실제 전송된 블록 기준이 아니다**
- 위 "후속 1·2"의 228/228 확인은 원본도 유효한 블록만 들어 있던 결과다(원본 무효 0건)
- 런타임 16마디(`--solo-line --comp`): `rendered` 32, fallback 0, 미스 0

## 정정: 코드 반영 지연은 채택 블록 기준 (Astra MEDIUM, #1595)
- 리포트가 생성된 첫 블록을 반영으로 셌다. 이제 인식 / 생성(다음 변화 전까지) / 채택(예약, 재생 완료 아님)을 따로 적는다. 블록마다 예약 상태를 적는다: adopted, fallback(실행 때 진행의 코드), not_consumed(null)
